## M0 工程骨架

**目标**：在写任何业务功能之前，把 AI 开发所依赖的基础设施搭好。

**范围**

- 单仓库结构：流水线、API、前端、部署配置、信息源配置各有独立目录。
- 根目录的 CLAUDE.md：架构概览、目录约定、常用命令、禁止事项。
- Docker Compose：Postgres + pgvector、API、worker、前端静态托管；本地和线上共用。
- 数据库迁移框架。
- CI：格式检查、类型检查（TypeScript strict、pyright）、测试。
- 合并到主分支后自动部署到 VPS，经 Cloudflare Tunnel 暴露、Access 保护。
- 健康检查接口和结构化日志。

**不做**：任何抓取、AI 或业务页面。

**验收标准**

- 提交一个 PR，CI 全绿，合并后自动部署成功。
- 通过域名访问，先要求登录，登录后看到占位页和健康检查结果。
- 服务器没有开放任何入站端口。

## M1 MVP：验证聚类与评分

**目标**：用最薄的端到端链路，验证事件聚类和评分是否符合我的直觉。

**范围**

- 20–30 个有官方 RSS 的中英文源，写在配置文件里。
- 每 30 分钟增量抓取，按 URL 去重，抽取正文。
- 小模型生成摘要，统一输出中文（原文链接保留）。
- embedding 加增量事件聚类。
- 评分：客观信号分 + LLM 重要性分（按评分细则），暂不含个人相关分；权重做成配置。
- 实时事件流页面：按分数排序；事件卡片显示摘要、各来源原文链接、分数构成和评分理由。
- 基础运行报告：抓取失败的源、当日 LLM 花费。

**不做**：观点对比、日报周报月报、反馈、破圈区、经典库、RSSHub、X、B 站、PWA 离线。

**验收标准**

- 连续无人值守运行 7 天，没有中断。
- 日均 LLM 花费在预算内（月度折算不超过 50 美元）。
- 随机抽查 20 个事件，聚类明显错误（该合没合、不该合合了）不超过 3 个。
- 每个事件都能点到原文。
- 我连续使用 1–2 周，记录排序不合直觉的案例，作为调参和后续里程碑的输入。

验收执行记录（2026-10-09）：七天无人值守的集中验收经用户决定跳过，改由日运行报告持续观察；"连续使用并记录案例"跨入 M2 期间继续进行；其余各条的验收结果见 `docs/tasks/m1.md` 验收记录。

## M2 观点对比与日报

**范围**

- 自建 RSSHub，信息源扩到初版清单的规模（约 100 个），并为每个源加上地区和类型标签。
- 对来源足够多样的事件生成观点对比：并排展示各来源的说法，指出分歧点，每条说法可追溯到原文。
- 每天固定时间生成日报。
- 响应式布局与 PWA：可安装到手机桌面，日报可离线阅读。

**验收标准**

- 观点对比中每一条说法都附来源链接，抽查无张冠李戴。
- 日报连续 7 天按时生成。
- 手机断网状态下可打开当天日报。

M2 首轮收尾审计（2026-10-10）：T1–T9 已完成开发/本地体验验收，T10 进行中。生产当前 63 源，低于原 80–100 的交付口径，需用户决定；不为凑数降低可用性要求。观点说法与链接归属全量通过，但抽查的年份幻觉、短正文摘要扩写与分歧判断待修复复验；日报仅有当日 15:35 补生成一期，尚无连续七天按时证据；手机生产离线安装实测待用户结果。完整记录见 `docs/acceptance/m2-2026-10-10.md`。M2 尚未关闭，需完成这些项目并由用户确认后再开 M3 任务板。

后续状态（2026-10-12）：#43 已合并内容质量补强并通过本地评测与页面验收（见 `docs/evaluations/README.md`），生产受影响事件修复与新样本复验仍需记录。上述日报数量、源健康与成本是首轮快照；本次未复查生产，不将其视为 10 月 12 日现状。七天日报、手机实测与 63 源口径仍未完成验收，T10/M2 保持开放。

## M3 反馈与破圈

排期方向（2026-10-12 讨论）：后台查询版 → 实时事件流排序及阅读体验 → 后台操作能力 → 兴趣与破圈。后台六页、全部运行成本、周期账目/提醒、查询与操作规则已逐项确认，见 [后台设计](superpowers/specs/2026-10-12-admin-workspace-design.md) 与 D-015；各子项目分别计划与验收。事件流多排序与默认“最新事件”见 D-014；M3 正式开工仍遵循 M2 收尾与任务板确认流程。

**范围**

- 实时事件流多排序：默认“最新事件”，按所属来源最早有效报道时间倒序；支持当前热度、重要优先，重复报道不能把旧事件作为新事件置顶。最新进展在实质进展识别完成后加入；阅读状态与时间筛选遵循需求文档。
- 反馈按钮：点赞、不感兴趣、已读。
- 兴趣画像与个人相关分，只作用于兴趣区。
- 破圈区：按 20% 比例轮换未选领域，不读取反馈，优先长期未接触的话题。
- 评分按领域归一化。
- 标准事件集评测接入 CI。
- 管理后台：默认总览，任意日期查询全部运行成本、源、文章/事件与运行历史；固定费用周期规则、付款确认及站内续费提醒；后续任务队列、聚类纠正、配置 PR 和有限临时覆盖。手动付费操作遵守预算，额外额度须按次授权并审计。

**验收标准**

- 首次访问默认最新事件，切换后记住用户选择；晚抓旧闻和旧事件新增重复报道不作为新事件置顶，报道时间与系统处理时间明确区分。
- 后台自然日/历史区间查询与明细一致，当前状态独立标注；全部运行成本区分期间成本与实际支出，周期账目不重复生成，充值与调用不双计。
- 手动任务去重、记录结果与费用，额外预算授权可追踪；配置修改只有部署后才标为生效，临时覆盖可解除/到期，聚类纠正不改写历史日报。
- 连续反馈一周后，兴趣区排序有可观察的变化。
- 实时流和日报中破圈区占比稳定在 20% 左右。
- 修改提示词或模型时，评测不达标的 PR 无法合并。

## M4 趋势与周报月报

**范围**

- 趋势检测：识别一周内持续升温的话题。
- 周报：聚合一周事件并去噪，突出趋势。
- 月报：深度综述，并追踪前期热点的后续进展。

**验收标准**

- 周报、月报按时生成，每个结论都能追溯到具体事件和原文。

## M5 经典库

**范围**

- 按兴趣领域和破圈领域分批导入精选历史内容，之后定期增量补充。
- 事件下附"延伸阅读"，从经典库检索同主题旧文。
- 日报或周报增加"旧文精选"栏位。

**验收标准**

- 各领域都有经典内容覆盖。
- 抽查 20 个事件的延伸阅读，大部分确实相关。

## M6 扩展信息源

**范围**

- 接入 X：热点与关注的博主，先确认接入方式和费用。
- 接入 B 站：热门、排行榜和关注的 UP 主，只取元数据，作为热度信号和相关视频链接。

**验收标准**

- 新源稳定抓取 7 天，失败会出现在运行报告中。
