# 开发路线图

这份路线图是交给 AI（Claude Code）执行的任务书。每个里程碑写明目标、范围、不做什么和验收标准；一个里程碑验收通过、并且我试用一段时间后，才进入下一个。需求细节以"需求文档"标签页为准。

| 里程碑 | 目标 | 核心产出 |
| --- | --- | --- |
| M0 | 工程骨架 | 仓库、CI、部署链路跑通 |
| M1 | MVP：验证聚类与评分 | 实时事件流 |
| M2 | 观点对比与日报 | 扩源、观点对比、日报、PWA |
| M3 | 反馈与破圈 | 兴趣区、破圈区、个人相关分 |
| M4 | 趋势与周报月报 | 趋势检测、周报、月报 |
| M5 | 经典库 | 批量导入、延伸阅读 |
| M6 | 扩展信息源 | X、B 站（元数据） |

## 开工前的准备（人工完成）

- [x] 租一台 VPS（Linux，建议 2 核 4GB 起步）
- [x] 准备域名，接入 Cloudflare，开通 Tunnel 和 Access
- [x] 申请 LLM API key，并在控制台设置每月花费上限
- [x] 建 GitHub 私有仓库
- [ ] 标准事件集人工打分（M1 试运行期间完成即可，M3 之前必须完成）

## M0 工程骨架

**目标**：在写任何业务功能之前，把 AI 开发所依赖的基础设施搭好。

**范围**

- 单仓库结构：流水线、API、前端、部署配置、信息源配置各有独立目录。
- 根目录的 CLAUDE.md：架构概览、目录约定、常用命令、禁止事项。
- Docker Compose：Postgres + pgvector、API、worker、前端静态托管；本地和线上共用。
- 数据库迁移框架。
- CI：格式检查、类型检查（TypeScript strict、pyright）、测试。
- 合并到主分支后自动部署到 VPS，经 Cloudflare Tunnel 暴露、Access 保护。
- 健康检查接口和结构化日志。

**不做**：任何抓取、AI 或业务页面。

**验收标准**

- 提交一个 PR，CI 全绿，合并后自动部署成功。
- 通过域名访问，先要求登录，登录后看到占位页和健康检查结果。
- 服务器没有开放任何入站端口。

## M1 MVP：验证聚类与评分

**目标**：用最薄的端到端链路，验证事件聚类和评分是否符合我的直觉。

**范围**

- 20–30 个有官方 RSS 的中英文源，写在配置文件里。
- 每 30 分钟增量抓取，按 URL 去重，抽取正文。
- 小模型生成摘要，统一输出中文（原文链接保留）。
- embedding 加增量事件聚类。
- 评分：客观信号分 + LLM 重要性分（按评分细则），暂不含个人相关分；权重做成配置。
- 实时事件流页面：按分数排序；事件卡片显示摘要、各来源原文链接、分数构成和评分理由。
- 基础运行报告：抓取失败的源、当日 LLM 花费。

**不做**：观点对比、日报周报月报、反馈、破圈区、经典库、RSSHub、X、B 站、PWA 离线。

**验收标准**

- 连续无人值守运行 7 天，没有中断。
- 日均 LLM 花费在预算内（月度折算不超过 50 美元）。
- 随机抽查 20 个事件，聚类明显错误（该合没合、不该合合了）不超过 3 个。
- 每个事件都能点到原文。
- 我连续使用 1–2 周，记录排序不合直觉的案例，作为调参和后续里程碑的输入。

## M2 观点对比与日报

**范围**

- 自建 RSSHub，信息源扩到初版清单的规模（约 100 个），并为每个源加上地区和类型标签。
- 对来源足够多样的事件生成观点对比：并排展示各来源的说法，指出分歧点，每条说法可追溯到原文。
- 每天固定时间生成日报。
- 响应式布局与 PWA：可安装到手机桌面，日报可离线阅读。

**验收标准**

- 观点对比中每一条说法都附来源链接，抽查无张冠李戴。
- 日报连续 7 天按时生成。
- 手机断网状态下可打开当天日报。

## M3 反馈与破圈

**范围**

- 反馈按钮：点赞、不感兴趣、已读。
- 兴趣画像与个人相关分，只作用于兴趣区。
- 破圈区：按 20% 比例轮换未选领域，不读取反馈，优先长期未接触的话题。
- 评分按领域归一化。
- 标准事件集评测接入 CI。

**验收标准**

- 连续反馈一周后，兴趣区排序有可观察的变化。
- 实时流和日报中破圈区占比稳定在 20% 左右。
- 修改提示词或模型时，评测不达标的 PR 无法合并。

## M4 趋势与周报月报

**范围**

- 趋势检测：识别一周内持续升温的话题。
- 周报：聚合一周事件并去噪，突出趋势。
- 月报：深度综述，并追踪前期热点的后续进展。

**验收标准**

- 周报、月报按时生成，每个结论都能追溯到具体事件和原文。

## M5 经典库

**范围**

- 按兴趣领域和破圈领域分批导入精选历史内容，之后定期增量补充。
- 事件下附"延伸阅读"，从经典库检索同主题旧文。
- 日报或周报增加"旧文精选"栏位。

**验收标准**

- 各领域都有经典内容覆盖。
- 抽查 20 个事件的延伸阅读，大部分确实相关。

## M6 扩展信息源

**范围**

- 接入 X：热点与关注的博主，先确认接入方式和费用。
- 接入 B 站：热门、排行榜和关注的 UP 主，只取元数据，作为热度信号和相关视频链接。

**验收标准**

- 新源稳定抓取 7 天，失败会出现在运行报告中。

## 二期

- B 站视频内容理解：字幕读取或语音转写，纳入摘要和观点对比。
