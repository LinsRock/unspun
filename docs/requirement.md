# Unspun 新版需求草案

更新日期：2026-10-20。状态：核心方向已确认，R1 已完成最终验收结案；用户现已要求进入 R2 并完成实施设计与任务拆分，见 [R2 任务板](tasks/r2.md)及 [D-029](decisions.md)。R2-00–03 已完成设计、冻结基线、扫描/处理配额分离及候选/详情解耦；本批 PR/部署结果见 R2-03 验收记录，R2-04 及以后待实施，R3 未启动。功能细则与未确认默认值仍按证据收敛，不补造用户评分；R1 的中间交付授权与证据保留在 D-025。产品定义见[产品重定义](product-definition.md)，实现建议见[重构方案](implementation-proposal.md)，交付顺序见[路线图](roadmaps.md)。旧版需求完整保留在[历史需求](requirement-legacy-2026-10-15.md)。

## 产品目标

Unspun 持续替用户采集、过滤和精选感兴趣的信息，既帮助用户跟上重要动态，也带来值得读、值得看的文章、视频、帖子和讨论，减少跨平台寻找、重复浏览和筛选的时间。

“值得看”可以来自事情重要、正在热议、兴趣相关、内容有质量或有趣。重要性、热度、时效与兴趣分别判断；影响范围较小的内容也可以值得推荐。

## 用户确认的第一阶段范围

- 覆盖对世界重要的领域，并收集个人感兴趣的信息；社保讨论、华为汽车相关问题、AI 最新技术动态是兴趣例子，不是完整清单。
- 来源以国内平台和中文信息源为主，内容可以涉及全球，保留少量国际大源补充。
- 自动发现同时覆盖时事与时效性较弱的内容，手动收集外部链接以后再加。
- 打开后看当天精选和持续更新的信息流；信息流提供简明整理，点击进入包含 AI 导读、全文或原文的详情。
- 信息流默认推荐，可切换最新；当天精选随重要新增适度更新。
- 兴趣通过关注领域或话题及感兴趣或不感兴趣反馈表达，也允许补充喜欢的作者与来源。
- 大事件的 AI 影响分析或预测留给后续阶段评估。

沿用既有单用户自用场景，电脑和手机均可阅读。已确认的默认排序与精选更新原则直接用于设计，下面的页面布局、具体参数和反馈细则仍为建议方案。

## 内容范围与组织

重要领域初步包含政治与国际关系、经济与金融、社会与公共政策、科技与 AI、医学与公共健康、气候环境与能源及重大科学进展。历史、思想、文化艺术、生活经验等同样可以通过内容质量和兴趣入选。具体分类允许增补，不要求每天每个领域有固定名额。

| 概念 | 含义 | 示例 |
| --- | --- | --- |
| 领域 | 持续覆盖和表达偏好的类别 | AI、公共政策、经济、文化 |
| 话题 | 一件事或围绕某个问题的持续讨论 | 某次发布、某项政策的讨论、某个产品相关争议 |
| 内容 | 可以独立消费的一篇材料 | 文章、帖子、视频、报告、访谈 |
| 热度观测 | 某个平台在某个时刻的关注信号 | 榜单位置、互动量、上榜时间 |

文章不必属于事件即可入选。话题可以关联多篇材料，一篇材料也可能涉及多个话题；同一企业的不同事件不能仅因主体相同被混为一件事。领域不直接等于话题，内容形式也不决定时效。

第一阶段自动发现主要来自持续采集的来源、榜单、栏目和已支持的作者更新。允许发现旧的好内容，保留原始日期；全面挖掘历史内容以后逐步扩展。

## 自动发现与来源覆盖

来源需要共同提供重要动态、公共讨论和优质内容，兼顾报道、原始发布、社区与独立创作。平台用于发现内容，具体作者与原始发布方提供出处，不能把平台名直接当作文章作者或独立证据。

每个来源记录覆盖领域、内容类型、获取方式、更新频率、可得正文范围和运行健康。核心领域缺少有效来源时记录覆盖缺口；不能因为采集量大就宣称覆盖充分。

关注作者或来源后，在已有接入能力范围内自动发现其更新并影响推荐。暂不支持的作者或来源明确显示待接入，不把保存偏好当作已经开始采集。

用户指定的首批新增或保留范围如下，实际接入状态与栏目选择详见[信息源接入计划](source-plan.md)。指定名单不代表当前已经接入成功，暂时不可采的来源保留待解决项与原因。

| 分类 | 指定来源 |
| --- | --- |
| 新闻 | 新华网、联合早报（中国与国际）、南方周末、澎湃新闻、人民日报、新京报、界面新闻、网易新闻、腾讯新闻 |
| 科技 | 36氪 |
| 知识 | 知乎日报、知乎热榜、豆瓣 |
| 财经 | 雪球、财富中文网 |
| 生活 | 微博 |
| 国外 | BBC、纽约时报、华尔街日报 |

此次为新增与保留优先范围，原有优质内容和视频候选继续按覆盖需要验证。国际综合主干按指定三家收敛。微信公众号与小红书列入后续探索，具体采集能力另验。

## 筛选与内容整理

采集留存、内容入选、推荐排序和当天精选分别记录，入库不等于推荐。明显重复、无阅读价值的纯推广、明显过期的短期消息优先轻量筛除；未知时间、材料不足和技术失败分别处理，不直接记为内容低质量。

相同 URL、明确转载和相同正文优先去重，但保留来源观测关系。同一事件的不同有效观点、解释和体验可以继续作为独立阅读内容；纯重复转载不产生新进展或新的推荐机会。

新闻检查当前时效和新增信息；文章、视频、经验与分析检查质量、兴趣和适用性。所有内容保留原始时间，系统发现时间、榜单观测时间和处理时间单独记录，不能让旧闻因晚抓取再次成为最新消息。

报道、评论、个人经历与传闻按各自性质表达。AI 简明整理和导读忠于实际材料，有来源依据；单源内容可以入选，报道数量不等于被多次独立验证。具体准入需要按内容类型设计，不能把所有内容都要求为新闻式事实摘要。

## 首页与持续浏览

建议首页同时提供当天精选和持续信息流，具体布局通过原型体验确定。

| 部分 | 建议行为 |
| --- | --- |
| 当天精选 | 从合格内容中再选编，覆盖值得关注的事与值得消费的内容，支持按需查看详情 |
| 持续信息流 | 展示更广的合格候选，包含话题和独立内容，持续更新 |
| 卡片 | 标题、简明整理、类型、来源与原始时间；按需要补充推荐理由、作者或视频时长 |
| 领域筛选 | 缩小当前浏览范围，不要求用户先选领域才能看到内容 |

当天精选随重要新增适度更新，显示更新时间；不沿用旧版固定日报的更新方式作为新版规则。数量设上限且允许不足，具体数量、重要新增的判定和更新间隔由样本与阅读体验确定。

持续信息流默认“推荐”，提供“最新”切换，关注兴趣的同时保留重要领域覆盖。推荐结合兴趣、阅读价值、当前价值和多样性；最新按照内容原始发布时间或有依据的话题进展排序。新发现的旧文可以进入推荐，但明确原始日期；新写的导读和转载不能使其进入最新前排。日期未知明确标注，不回填采集时间冒充发布时间。

新版混合流默认排序已由 D-024 确认，取代 D-014 的新版默认最新要求；报道时间与处理时间分开的原则保留，运行切换随实施交付。浏览或展开内容不推断已读，也不因此移除内容，沿用 D-021。

## 详情阅读

| 详情类型 | 需要提供的阅读内容 |
| --- | --- |
| 话题详情 | 简明概况、AI 导读、背景、重要进展或讨论焦点、相关报道与精选内容、出处入口 |
| 文章或帖子详情 | 标题、作者、来源、原始时间、AI 导读、可得正文、原文入口 |
| 视频详情 | 标题、作者、来源、原始时间、简介或有内容依据的 AI 导读、视频播放或原视频入口 |

话题根据实际材料组织内容，不要求每件事都有观点对比或完整时间线。AI 导读说明主要内容、背景、观点与阅读价值，和原文清楚分开；后续预测能力不混入当前导读。

可取得全文时支持站内阅读，保留段落、出处与正文完整度。只能获取部分材料时显示可读范围与原文入口，导读只基于实际取得的内容。视频没有字幕或实际内容依据时，可提供明确标注的简介整理，不生成观看全片后的结论、引文或时间点。

从当天精选和信息流进入同一对象的详情。生成或审核中的导读显示状态，失败可恢复；已经合格的卡片与可读原文不因可选导读延期被误判为低质量。中文卡片及生成内容的证据要求继续适用。

## 兴趣与反馈

用户可以关注或取消关注领域与话题，补充喜欢的作者与来源，并对话题或独立内容表达感兴趣或不感兴趣。偏好跨设备保存，反馈可修改或撤销。

初始偏好来自显式关注；没有反馈也要能推荐。反馈影响后续个性化排序，单条不感兴趣不自动推定整个领域都不喜欢，喜欢某篇文章也不等于认可其中每个观点。作者与来源偏好不能取代重要领域的基础覆盖。

第一阶段先采用可解释的标签、主题匹配与显式反馈；不依赖点击时长或滚动推断兴趣。反馈立即保存，下一次推荐计算反映变化，具体权重与作用范围用同批候选对照验证。

2026-10-18 R1 用户终验确认“有小问题但可接受”，要求收尾阅读页：同篇多个要点的共同来源归属集中标注，避免反复出现“文中称”，保留观点、评价、问题和简介的材料边界；感兴趣/不感兴趣改用拇指图标，支持明确的选中与撤销状态及无障碍名称；移除阅读价值技术判断说明和顶部“中文阅读 · 原文可溯”，切换推荐/最新静默保存，异常仍可见；页面和局部操作采用清晰的加载状态。该确认不补造逐条用户评分、手机或外站播放结果，也不授权启动 R2/R3。

## 运行与约束

- R2 先建立近期供给与选材基线，分别记录来源、元数据采样、材料、付费尝试、合格准入及当前展示；来源覆盖、已采集范围的筛选召回与用户值得看比例使用不同分母。采集范围、材料获取与付费整理的配额分别控制，具体参数见 [R2 实施设计](superpowers/specs/2026-10-19-r2-topics-and-recommendation-design.md)，未取得用户评价时保持未测。
- R2 话题与内容采用多对多关系，进展须有实际材料和明确时间依据；同主体不直接归并，转载和导读更新不冒充进展。合格旧材料退出推荐时效窗口后仍可作为背景阅读，详情继续校验当前审核、来源及材料发布范围；具体契约在对应实施批次固定。
- 复用现有自用访问方式、技术栈和部署基础；新增能力以增量迁移接入，保留历史内容、日报、费用和验收记录。
- 用户已要求分阶段清理旧代码/worker、旧/无用文档、无用/过时数据及相关开发残留，执行安排见[清理任务板](tasks/cleanup.md)和 D-031。无引用的草稿、重复件、垃圾材料和可重建临时数据按精确清单回收；有历史阅读、评测或审计价值的内容保留或归档。推荐过期不自动触发存储删除，具体保留期限、引用保护与恢复方法由对应清理批次固定。
- 继续按来源配置采集周期与失败退避；采集、付费处理和首页选编互不因单个慢任务整体阻塞。
- 原产品预算范围为每月 20–50 美元；当前实际执行仍服从 D-027/D-028 的项目 $15/月、生产 $13.50 与原评测累计 $1.50 分配，以及提供方实际剩余额度。分类、摘要、导读、审核、embedding、话题判断与重试都计入共享总额，先测单位成本，不隐式增加预算、更换模型档位或释放未知预留。
- 后台优先复用已有健康、内容、任务和费用查询，补齐内容入选或未入选的原因；核心阅读路径优先。
- R1 页面由 AI 提供真实 API 本地预览并完成中间验证、审查和 PR 合并，用户只做 R1 最终体验验收；其他批次的页面仍沿用 D-012。评分与提示词变更继续执行固定样本评测，AI 技术判断与用户主观评价分别记录。
- R1 实施前停用旧生产 AI worker，后续普通部署不得重新拉起；R1 处理仅在任务隔离、总预算与来源门槛满足后受控启用。

## 第一阶段验收

下列指标在首轮真实样本验证后固定基线、观察窗口和阈值，再用于实现验收。既评入选内容，也评被排除的内容；已采集范围内的算法召回和端到端的来源覆盖分别报告。

| 维度 | 验证内容 |
| --- | --- |
| 覆盖 | 人工参考的重要动态、公共讨论与好内容有多少被发现，遗漏属于来源还是筛选问题 |
| 精选 | 入选内容中用户觉得值得看的比例，重复推荐比例，有价值内容被误筛的情况 |
| 兴趣 | 同批候选在关注与反馈前后的变化，无反馈时是否仍有可读内容 |
| 整理 | 话题是否误合并，不同内容是否被误去重，观点与传闻是否有正确归属 |
| 时效 | 旧闻和转载不伪装成最新，有价值旧文有明确日期，真正进展可被发现 |
| 阅读 | 卡片至详情路径、全文与部分正文状态、原文入口、手机和电脑阅读均可用 |
| 成本与恢复 | 处理成本可追踪，重复输入复用已完成结果，慢源、预算不足、失败重试与重启可恢复；已发生费用保留 |

复用历史用户标注而不改写其含义，补充独立文章、视频、社区讨论和当前国内来源样本。三个用户例子在具体指代明确前仅用于需求说明，不作为已经发现或验证的事件案例。

## 后续范围

手动收集链接、微信公众号、小红书、完整历史内容挖掘、更多全球来源、跨期报告、通知分发及大事件 AI 影响分析后续分别评估。收藏、稍后看和站内搜索暂列辅助需求，不作为本轮核心体验的前置条件。
