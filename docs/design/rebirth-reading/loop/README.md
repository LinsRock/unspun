## 执行范围

- 正式发现源为量子位、IT之家、Solidot 的公开 RSS，以及保留失败结果的 36kr RSS 探测。每源取返回顺序的前 8 项，近期窗口 14 天；所有成功条目及失败源都进入记录，不以推广或访问失败为由缩小分母。
- 首次发现后，按明确理由选择最多 12 项取正文。每个运行批次累计最多 24 次 HTTP 请求（含重定向），每次响应最多 2 MB、超时 10 秒。一次后续观察使用独立运行 ID，比较新增和缓存复用，原批次保持可追溯。
- 采集程序自动发现、规范 URL、去重、记录日期和读取范围。本次会话负责编辑选编与有依据的正文整理；独立发布校验通过后生成不可变阅读快照。程序不根据抓取成功直接发布，不把会话编辑称为无人值守自动写作。
- 无模型 API、密钥、数据库迁移、生产接入或常驻调度。当前 Python 标准库采集脚本与 Node 原型均为试验实现，不据此确定正式后端技术栈。
- 原版和第二版材料、反馈与预览保留；本轮按独立版本保存反馈。真实关注信号未接入，热点质量保持未测。

## 判断方法

记录发现、正文获取、选编和发布的各自分母及原因。候选未取正文、正文失败、日期未知分别保留，不冒充低质量淘汰。每项入选内容必须对应实际抓到的材料；补充核对的外部一手来源单列，不计入自动发现覆盖。

记录原发时间、发现时间及本轮可读时间。首次抓取历史积压只反映初始发现延迟，不能据此宣称持续实时更新；短时重复观察只检验新增识别及重复输入处理，不能证明多日稳定性。编辑结果继续由用户阅读判断。

程序记录 HTTP 次数、响应字节和耗时；前置只读信源探测与正式采集测量分开。外部模型 API 调用为 0，模型单条成本、用量和吞吐量未测；本次会话整理不能换算成自动服务的零成本。

## 使用与复核

```sh

  --publication "$PWD/docs/design/rebirth-reading/loop/published-batch-a.json"
```
