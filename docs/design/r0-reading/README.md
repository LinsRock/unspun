## 启动

在仓库根目录运行（Node.js 22 或更高版本，无需安装新依赖）：

```bash
node docs/design/r0-reading/server.mjs
```

打开 <http://127.0.0.1:4178>。端口冲突时可以设置 `R0_PREVIEW_PORT`。服务仅监听本机回环，提供静态资源和明确列出的只读材料端点；不连接生产 API、数据库、模型或 worker。

页面入口：

- [当天精选](http://127.0.0.1:4178/#/today)：6 条人工试排，条数上限与阅读密度可调整；不足上限不凑数。
- [推荐信息流](http://127.0.0.1:4178/#/feed)：18 个话题或独立内容入口；支持领域筛选与最新切换。
- [市场话题](http://127.0.0.1:4178/#/topic/market)、[健康政策话题](http://127.0.0.1:4178/#/topic/health)：逐条材料提示、相关内容及转载关系。
- [C14 文章](http://127.0.0.1:4178/#/content/C14)、[C07 预览](http://127.0.0.1:4178/#/content/C07)、[C03 视频简介](http://127.0.0.1:4178/#/content/C03)、[C24 日报版](http://127.0.0.1:4178/#/content/C24)、[C39 受限入口](http://127.0.0.1:4178/#/content/C39)：不同材料范围的独立详情。
- [选材评审](http://127.0.0.1:4178/#/review)：全部 43 个真实候选、先评 16 项、待评与已评、边界样本、覆盖缺口及页面体验建议。

## 真实材料与出处

页面直接读取[原候选文件](../../research/r0-2026-10-15/candidates.json)，没有重写其中的人工字段。标题、作者、原始发布方、发现渠道、原始日期、材料范围、限制和阅读提示均沿用该文件。阅读提示是已有来源报告中的线索，未经独立事实审核；没有新造事实结论、话题导读、视频观后结论或讨论总结。

上轮来源验证的原始响应仍留在本机 `/tmp/unspun-r0/raw`。以下命令可离线恢复 39 份已取得的公开文本：

```bash
server/.venv/bin/python docs/design/r0-reading/prepare_materials.py \
  --archive /tmp/unspun-r0/raw
```

脚本先核对原响应指纹，再复用候选中记载的选择器或提取方式，要求文本指纹与原候选完全相同。由原文块元素恢复段落，只调整空白，不增删源文本字符。浏览器再次核对候选集与文本指纹，失败的材料只保留原文入口。`materials.local.json` 是被 Git 忽略的本地阅读缓存；不把各站全文复制入版本库。不发起新请求，不调用模型，不绕过访问限制。原归档不存在时，仍可浏览卡片、出处和反馈，缺失文本明确显示未载入。

39 份文本包括 28 个公开文章文本单元、3 个日报编辑版、1 个短讯、2 个部分预览、2 个问题描述、2 个视频简介与 1 个播客简介。其余 4 个受限入口的候选文件没有保存可展示的原始导语/正文，页面只展示报告阅读提示与原文入口。公开文章文本不等于图片排版、授权付费全文或媒体内容完整。

## 选编与日期口径

`manifest.json` 只记录原型的人工版面顺序与关联建议，没有模型分数、用户评分或已经通过的选择结论。

- 默认推荐；最新按原始材料发布时间排序。仅有日期的材料在对应日期单列，不补零点或采集时间。日报时间标为选编时间，问题时间标为创建时间。
- C11 / C19 作为旧闻反例留在评审区，没有混进当前阅读流。C29 / C31 等旧文仍可评当前阅读价值，并保留原日期。
- C21 / C41 是同篇转载，流中不重复占位；C41 详情保留转载时间与原作日期。C20 / C42 只有部分重叠，两份完整页面的差异可在详情核对。C12 是另一篇文章，不一起误去重。
- 市场话题是相关材料的阅读组织试验，不认定 C01、C05 与 C28 都属于同一事件；问题入口不充当事实验证或完整讨论。
- 18:32 / 18:33 是用原有材料模拟的版本，后者在市场话题中加入 C05；不是历史出版记录、真实重要新增判定或线上自动更新。30 / 60 分钟等选项仅供收集偏好，没有固定阈值。

## 收集反馈

先从精选阅读几条，再进[先评 16 项](http://127.0.0.1:4178/#/review?filter=priority)和[边界样本](http://127.0.0.1:4178/#/review?filter=boundaries)。每篇详情下方分别填写：

1. 现在是否值得看：值得、不值得、还无法判断。
2. 个人兴趣与重要性：各 1–5，未填保留未知。
3. 建议位置：当天精选、推荐流、仅最新、不入选、材料不足待补。
4. 理由或建议。单条兴趣反馈只针对当前对象，不扩大成整个领域的判断，也不自动换算成分值。

话题评价单独保存，不传播到所有成员。页面体验区记录遗漏内容、阅读密度、精选上限和更新节奏。调整或撤销反馈后可继续回访内容，不自动标为已读或隐藏。

反馈仅保存在当前浏览器的 localStorage，按原候选文件 SHA-256 区分；不承诺跨设备同步。点“导出反馈”可下载 `unspun-r0-feedback-2026-10-15.json`，包含所有候选的原始出处、未填的空值、实际用户输入、话题意见、体验建议及候选集指纹。自动检查使用隔离 DOM 存储，不往用户浏览器写测试分数。导出文件没有自动上传或自动写回历史人工标注；后续评审再核对、固定基准。

浏览器自动检查受工具连接限制：IAB 不可用、Chrome 创建/连接标签页超时、原生应用未取得窗口。用户在 2026-10-16 明确确认原型体验通过，这是独立的 D-012 验收依据；没有补记真实浏览器渲染、400px/360px 无横溢、深浅主题或键盘焦点的逐项自动检查证据。响应式样式已提供，DOM 检查不能替代这些专项证据。

用户体验时请依次检查：

1. 精选中话题、社保预览、汽车长文、知识回答、人物视频与 AI 分析的组合是否想读；是否有该出现而遗漏的内容。
2. 从精选与信息流进入同一详情；在最新流中读 C14 后返回，排序、领域和位置是否保留。
3. C07 只显示预览，C24 仅日报版，C03 不假装有字幕，C39 不假装有正文；原内容与出处是否清楚。
4. 载入 18:33 模拟版，判断加入 C05 是否值得打断/更新；试 4 / 6 / 8 条上限、两种密度并留下建议。
5. 在桌面和手机宽度检查长标题、正文、底部导航、表单及深浅主题；保存、修改、撤销并导出实际反馈。
