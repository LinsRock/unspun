# R1 部署前预算与消费者预检 · 2026-10-17

生产开启付费阶段之前，不能靠手动 SQL 或直接修改运行容器建立账务策略。正常 PR 部署现在在目标镜像迁移后、服务启动前，先只读构造目标 R1 配置；只有确实配置了 R1 paid 来源，才执行既有 `initialize-production` CLI，再执行消费者 `--check`。

初始化只读获取同一个提供方 key 的真实累计/月度计数，在原生产库保留已发生费用及 carry；已启用策略不会因再次部署被重置或自动扩额。消费者继续检查生产 scope、版本、key 指纹、提供方锚点和 incident。任一步失败都不会启动目标服务；旧 AI worker 始终 `worker=0`。

当前所有来源阶段仍关，配置探针返回 `unpaid`，预算初始化和付费预检均跳过。探针没有数据库、来源或提供方请求；没有启动消费者。目标 Linux 现有 API 镜像内实际执行同一探针源码也返回 `unpaid`，[哈希与零调用证据](r1-budget-rollout-hook/linux-probe.json)保留。

`bash -n` 通过；部署故障注入完整 **17 项通过**，覆盖迁移→初始化→预检→启动顺序、关闭阶段不初始化、预算/预检失败和非法探针结果不启动，以及既有中断/镜像复用/旧 worker 零副本边界。该批不改后端模型、数据库 schema、预算上限、配置来源名单或 worker 副本。

这是 16 的启用准备，不代表 G1/G2/G3、费用投影或生产发布通过。正式启用仍需独立范围固定的来源配置 PR；回退关闭 R1 阶段并恢复零副本，保留任务、账本和增量表。
