## 1. 依据、确认边界与 R1 出口

执行时先读 [CLAUDE.md](../../CLAUDE.md)、[决策日志](../decisions.md)，再读本任务。产品依据为[产品定义](../product-definition.md)、[需求](../requirement.md)、[实现方案](../implementation-proposal.md)、[路线图](../roadmaps.md)及[指定来源计划](../source-plan.md)。证据为 [R0 任务](r0.md)、[来源验证报告](../research/2026-10-15-r0-source-validation.md)、[43 个候选](../research/r0-2026-10-15/candidates.json)、[原型说明](../design/r0-reading/README.md)和 [2026-10-16 验收记录](../acceptance/r0-reading-2026-10-16.md)。不恢复旧 M3-A–G 的排期。

| --- | --- |
| 已确认 | 国内平台和中文源优先；自动发现；独立文章、帖子、视频可入选；推荐默认并可切换最新；关注与可撤销反馈；阅读不自动隐藏；原始时间和材料范围如实呈现 |

R1 的交付是：**真实来源定时发现 → 留存候选及出处 → 去重与材料获取 → 内容型整理和审核 → 独立推荐/最新流 → 内容详情 → 关注与反馈改变下一次推荐**。不要求先创建 `Event` 或 `Topic`，至少验证开放文章、有限材料入口、视频简介与原视频入口三种阅读路径；视频能力只按实际材料申报。

R2 承接话题实体、成员归并、实质进展和混合流；R3 承接当天精选、完整首页、覆盖补齐及第一阶段持续使用验收。R0 原型里的人工话题、18 个试排入口、6 条精选、模拟版本和 30/60 分钟选项均不成为 R1 运行规则。R1 不实施手动收集、预测、通用后台操作平台、全文付费访问或新的账号体系。

配置按路径记录采集器、publisher/平台、覆盖领域、内容形式、材料能力、周期、退避、依赖和阶段开关。已有参数只是运行基线：全局 30 分钟采集、RSSHub 1800/3600 秒缓存、512 MiB 上限都不是用户确认的新版产品参数。扩大路径和调整生产配置分别在实际 PR 中给出前后差异、单位成本及回退方法。

## 4. 实施契约

### 4.1 内容、材料与新旧流水线归属

保留 `articles.id` 为正式内容 ID，新增或关联以下职责，具体字段/索引在 R1-02 的迁移中固定：

| 职责 | 最小数据与约束 |
| --- | --- |
| 内容身份 | 内容形式（文章/帖子/问题/视频/音频等）、体裁（报道/观点/经验/简介等）分开；作者带平台身份与署名角色；平台、发布方、原作关系独立；未知可为空 |
| 来源观测 | 来源路径、平台条目 ID、发现 URL、规范内容 ID、观测时间、可得排名/互动量及单位；唯一键带来源命名空间。重复入库不丢多渠道观测，未提供互动量不补零 |
| 材料版本 | 取得时间、原文 URL/响应依据、源摘要与实际正文分开，存安全段落结构及指纹、抽取器版本；范围包括开放文本单元/日报编辑版/完整短讯/预览/问题背景/媒体简介/订阅导语/无材料；访问失败与完整度分开 |
| 时间 | 沿用 `reported_at/date/precision/basis`；另保留 feed 时间、修改/转载时间、日报选编/问题创建时间、观测与处理时间及冲突依据；旧字段不批量重释义 |
| 派生版本 | 内容特征、准入、卡片、可选导读分别有状态、理由、材料版本、契约/提示词/模型版本、审核依据；旧 `summary_grounding` 不自动成为新版通过凭证 |
| 去重关系 | URL/平台 ID 为第一层，正文指纹与明确原作关系为第二层；已有多行可关联规范内容，不删历史行/成员。部分重叠仅记关系，不合并不同文章 |
| 处理归属 | `processing_track` 建议为 `legacy/r1`，历史默认 legacy；R1 材料和派生结果另存版本，避免覆盖旧事件仍引用的正文/摘要。所有旧摘要、embedding、聚类入口及其积压查询明确排除 R1 owner |

来源路径也只有一个采集 owner。同一路径切入 R1 时停用其旧轮询，已在途任务需有交接检查；已有 URL 命中历史行先只记观测，只有明确范围的交接才转处理 owner，不全量迁移历史。跨来源的同篇内容按规范对象串行化付费任务，不能因新发现渠道重复付费；无法确定原作的材料保留不确定性。

只有元数据时仍可留候选；已有合格卡片、可读原文不因导读延期而消失。材料变化使对应派生版本失效，旧结果只能作为历史，不带着过期审核继续发布。复用要求材料、作者/时间等语义元数据、材料范围、抽取器、生成/审核契约及模型版本均匹配；不直接复用当前仅标题/正文 MD5 作为完整新契约。

### 4.2 任务、恢复与账务

复用 Postgres 与 worker，新增任务/尝试记录，按来源采集、材料获取、内容整理/审核、可选导读分队列；R1 不提前实现话题和选编消费者。

- 任务唯一键含阶段、对象/来源、输入与策略版本；来源周期任务有周期身份，不因定时扫描重复投递。提交新材料和后续任务用同一事务，避免“写入成功但任务丢失”。
- 短事务领取，使用行锁/`SKIP LOCKED`、领取期限及领取版本；网络调用不持有内容长事务锁。超时回收只恢复任务，不允许旧领取者覆盖新结果；幂等保存结果后再确认完成。
- 明确待执行、运行、重试等待、预算延期、材料不足/受限、已完成、终止失败；内容被排除另记准入理由。技术失败、未知日期和预算不足均不伪装成“不值得看”。
- 按源周期/退避与有限并发领取；采集/材料/付费队列与将来选编截止检查拥有独立执行机会。隔离环境可用无付费截止探针验证，生产不启动旧日报/AI 循环；不能在一个串行循环前后包一层任务表就宣称已隔离。
- LLM 每次实际 HTTP 请求（含客户端截断重试、embedding）先持久化 attempt 和预算预留，响应后独立提交实际用量，再以输入指纹和领取版本提交业务结果。解析、业务写入或后续阶段失败不回滚费用。
- 沿用每月 $20–50 的既有 LLM 预算范围与现有模型/供应商；实施时在范围内登记实际执行上限和阶段额度，不默认提高预算。总额检查覆盖 legacy/R1/重试；`$0.40/24h` grounding 限额继续是附加约束。预留须原子化，不能多个消费者各查余额后同时放行。
- 网络超时等导致是否计费未知时，记 `usage_unknown` 并保留预留待对账，不填零、不自动无限重试；缺 provider 费用也保留待核对。不能承诺外部调用严格恰好一次，只保证账务、结果和重试决策可追踪。

### 4.3 筛选、兴趣与发布

付费前先做确定性重复/无效条目筛查。明确过期的短期消息按已冻结类型规则跳过付费；旧长文、分析、知识及时间未知进入各自待判定路径，不套一个“7 天”有效期。分类、主题、当前价值和卡片整理尽量共用一次输入，生成沿用 summary 档、语义审核沿用 Flash；不更换模型、不把旧 scope/durability 事件分移植为内容价值。重要性、热度、阅读价值与兴趣分栏记录，缺少平台热度就保持未知；如确需新增模型重要性判断，继续使用现有 importance 的 Flash 档并单列成本/评测，不借合并调用把其降到 summary 档。

内容型契约区分“报道陈述”“作者主张/经验”“问题背景”“媒体简介”，保留归属和材料范围。卡片需有经过审核的中文标题与相对标题的有效增量；仅标题、无材料或审核未完成时不凑卡片。不因是评论就要求多源新闻证据，也不因热度高或来源知名跳过语义审核。导读单独检查观点归属、引文与材料范围；无字幕/实际视频内容时只能简介整理，没有观看结论、引文时间点或虚构字幕。

兴趣采用显式领域、话题词、作者与来源匹配。R1 的“话题关注”先是稳定的兴趣词/标签 ID，不冒充 R2 的事件/议题实体；后续映射要显式核对。作者身份带平台；保存偏好与实际自动采集能力分别返回，未支持作者更新显示待接入。用户例子不预填为其关注、分数或排除清单。

反馈只针对明确内容目标，可修改/撤销并保留版本；单条不感兴趣只降低该对象及有依据的有限相似匹配，不自动拉黑作者/整个领域或隐藏已读。无反馈仍有合格候选；推荐分别考虑基础覆盖、兴趣、阅读价值、当前价值及多样性，规则与权重在 R1-00B/09/12 的同批对照中固定。R1 不引入旧破圈比例或单中文/单地区折扣；旧接口的历史排序不因此改写。

## 8. 验证、发布与本轮交付检查

各实施 PR 按触及范围运行检查，数据库/恢复测试使用独立迁移后的 Postgres。数据库测试被跳过不能算通过；模型回归用隔离评测库、固定输入和已登记费用上限，保留首轮失败及后续重试。

| 改动类型 | 必要验证 |
| --- | --- |
| 纯文档/证据 | 本地检查相对链接、来源/代码引用、任务依赖、空人工字段、历史文件指纹与 diff；不因文档变更调用付费模型或启动生产业务，CI 仍按仓库既有流程运行 |
| 后端/迁移/任务 | `uv run ruff check .`、`uv run ruff format --check .`、`uv run pyright`、`uv run pytest`；隔离库 `alembic upgrade head`、必要的模型一致性/现有数据升级检查，以及并发/中断/重复任务/账务故障注入 |
| 评分/提示词/准入 | 旧冻结标准事件集严格命令（下方）、受影响的旧生成质量集及 R1 新内容集同输入对照；质量生成评测复用 [server/eval 流程](../../server/eval/README.md)及当前变更前冻结输出，不能仅凭未受影响的排序命令宣称提示词通过。引用匹配和自动规则之外做语义复核，分别报告实际用户判断、技术审阅及未知 |
| 页面 | `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build`；相关旧 PWA 行为回归；真实 API 本地预览与桌面/手机宽度/主题/键盘/返回检查；AI 自行提交/合并中间 PR，17 统一提交用户最终体验验收 |
| 来源/部署/启用 | 目标环境/版本与路径证据、新条目时效和材料、冷缓存/失败恢复、owner 交接、费用及回退；CI 绿后正常 PR 合并部署，不直接改容器/数据 |

旧标准事件集命令在 `server/` 执行，新增内容评测由 00 固定，不能用旧事件排序通过替代新内容质量：

```sh
uv run python -m unspun.evaluation.run_feed_ranking \
  --snapshot ../docs/evaluations/m3b/technical-candidates.json \
  --annotations ../docs/evaluations/m3b/technical-annotations.json \
  --output /tmp/r1-legacy-ranking-report.json
```

R1 最终按以下证据验收，不给尚未确定的内容指标填目标数字：

1. **自动发现与阅读**：目标运行的新内容有来源/观测/材料版本及任务链；至少开放文章、有限正文和视频简介/原片入口走通。无需事件 ID；卡片至详情、原文与 AI 分开、返回位置可用。
2. **选材与时间**：用冻结入选/排除样本检查值得看、误筛、重复和时效；有价值旧文保留日期，旧闻/转载/新导读不刷新最新；问题、日报版、预览和媒体简介不越界。未取得的主观评价继续为空。
3. **兴趣**：同批输入与算法版本下，实际关注/反馈前后及撤销后的排序和理由可对照；无反馈仍能推荐，单条不感兴趣不扩大为领域否定；实际采集能力与偏好保存分开。
4. **恢复与费用**：重复提交复用，慢源隔离、预算延期、重启/过期领取、材料修改和审核失败可恢复；已发生费用与未知费用保留，所有用途共享总额，单位成本及真实流量月度范围可核对。
5. **范围对账**：来源按路径标记观察/已启用/受限/待接入，来源缺口和算法遗漏分别报告。R0 未完、专项失败、R2 话题与 R3 精选依赖继续列明；正式页面通过本轮用户体验后才结案。

每个交付 PR 审查差异及受影响调用方，修复后增量复审并运行相关检查；有实质新变更或未决疑点再扩大完整验证。在同一 PR 更新已完成检查项与新增证据，不重复历史报告；工具/材料不支持的检查明确未执行，不补成通过。CI 按影响范围选择检查，固定汇总检查必须通过；阶段验收可手动触发完整检查。AI 自行提交、处理 CI 和合并，不逐项索取许可。增量表、任务与费用在回退时保留，旧日报不重写，不删列/删表，普通部署不恢复旧 worker。用户只验收 R1 最终结果；预算扩大及 R2/R3 不在本次授权范围。
