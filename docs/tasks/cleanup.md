## 3. 分类规则

### 文档

- 当前规范和执行入口保持精简、一致，明确当前阶段与替代文档；未来会话从 README、CLAUDE、需求、路线图和活动任务板进入。
- 已被替代但包含决策原因、用户确认、未结事项或验收事实的文档归档并标明历史适用范围。历史索引引用唯一原件，避免为归档再复制一套全文。
- 无独有信息且没有业务/评测引用的重复草稿、临时交接和废弃原型可删除；先把仍有效的待办、约束或样式资源合入唯一当前入口。
- 移动文档或归档过程数据时同 PR 更新链接，并核对程序/测试实际依赖。当前执行登记必需的冻结输入、模型首次输出、未结费用与停止标记保持原路径和字节；用户已同意将无当前用途的历史过程产物存入固定 Git 版本，即使它们曾被全目录清单收录。核验恢复字节，历史工具在对应完整版本复现，不改旧哈希迁就当前目录。
- 清理完成既要减少重复文件，也要降低当前入口的歧义；不能只增加免责声明而让过时任务仍作为默认执行入口。

### 数据

| 数据类别 | 默认处理与允许回收的条件 |
| --- | --- |
| 已失时效的新闻/短讯 | 先退出适用的当前推荐窗口；按原始日期保存历史意义。是否删除存储另按保留策略和实际引用判断，旧背景/知识不统一按年龄过期 |
| 模板、空正文、验证页、重复失败响应 | 保留必要的来源诊断、关键失败样本及数量/原因摘要后，无引用的大块原始响应可归档或删除；不能删除冻结反例或当前材料指针所指记录 |
| 重复正文与旧材料/派生版本 | 先检查规范身份、别名、话题、反馈、审核与版本引用；只回收已确认无引用副本。规范 ID、原始时间与材料范围不能因去重改写 |
| 历史来源观测、诊断日志及已终态任务 | 可依据实际量设计分层保留/汇总/归档；终态任务和配额收据仍可能承担去重、处理配额、成本分母及恢复校验，须保留这些语义或明确迁移 |
| 临时测试库、导出和缓存 | 核对创建来源、活跃连接、预览/取证引用和是否有唯一内容；纯可重建临时数据可删除。原累计评测库及持有付费结果/账务的库不因名称含 quality/test 就判临时 |
| 历史内容、日报、标注及评测 | 保留仍需历史阅读/复现的内容和唯一原始证据；归档可调整载体，但须核验读回、哈希及引用，保留用户评分空值和原义 |
| 费用、未知预留及审计 | 保留物理调用、凭证、费用与预算关联，历史失败不抹去；清理不能释放未知预留、改变分母或把未确认费用结为零 |

保留期限由 CL-05 结合对象引用、实际体积/增长、读取需求和恢复成本确定，本轮不设置统一的“超过 N 天全删”。历史可读与费用可审计不要求永久保存所有无引用的大块缓存；每种载体的取舍和保留摘要必须明确。

### 开发与部署资源

- 合并 worktree/分支须无待保存修改、独有提交及活跃会话/预览，并确认不是共享 editable、符号链接或运行进程的依赖；使用对应 Git 操作，不对整个 worktree 目录做批量强删。
- 已停止容器、临时测试卷、构建缓存与旧镜像按精确对象及 owner 清理；保留当前版本和经验证的回退镜像、生产/保留评测库卷。不能用全局 prune 清理未辨明归属的资源。
- 现有生产备份配置为本地 14 天轮替，这是当前事实；评估过时备份前确认最新可恢复备份及所需历史范围。备份保留期调整和恢复检查单列证据，不把旧注释里的未实现异地备份当作已存在。
