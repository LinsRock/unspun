[registration-v1.json](registration-v1.json) 是实际离线登记报告：`registration_valid=true`、`technical_ready=false`、`user_quality_passed=null`。登记任务完成与 G1 解锁是两个不同结果。

- **已完成**：输入和引用可核对，旧主观标签一致，负面边界已登记，反馈导出有严格校验入口。
- **R1-00B 承接**：实际材料技术审阅、尚未参与调试的留出输入、变更前输出、技术期望和暂定参数、按路径周期固定的来源观察窗口与容错。缺这些证据不得把 G1 记为通过。
- **用户质量待最终验收**：本次没有提供或导入逐条反馈文件，新候选的主观判断保持未知。原型总体验收不转换成候选评分；缺中途评分不阻塞已授权的基础实现。
- **运行与覆盖待后续证据**：旧 worker 保持停用；路径当前能力、跨日稳定性、社区回答及实际媒体内容由后续任务取得。来源名单与启用名单分开。

指标、分母、成本和补样安排见[门槛登记](gates-v1.md)。本目录未固定精选条数、更新节奏、用户兴趣或新版内容排序规则。

## 复现

在 `server/` 执行，输出路径必须是新文件，避免覆盖原始证据或首轮失败：

```sh
uv run python -m unspun.evaluation.r1_inputs \
  --root .. --registry ../docs/evaluations/r1/inputs-v1.json \
  --output /tmp/unspun-r1-registration-check.json
```

退出码 0 仅表示登记有效；输入损坏返回 2。增加 `--require-technical-ready` 时，本版本返回 1，并如实写出 `technical_ready=false`，不能用登记成功替代 G1。R1-00B 会另行冻结并校验技术基准。

如用户实际提供原型导出的反馈，在命令中增加 `--feedback <文件路径>`。校验 schema、候选文件字节哈希、完整候选集合、逐项出处与材料指纹、两处评价的一致性、分数类型/范围、目标 ID、实际填写数和带时区时间；不接受布尔值冒充数字分数，不丢弃错误后继续宣称导入成功。只有实际填写的对象进入独立报告，未填写字段仍为 null，话题和体验建议分开保留。文件格式和哈希不能证明填写者身份，报告明确 `identity_verified=false`，仍需记录用户提供该文件的出处。

没有反馈文件时不创建空白“用户评价版本”。校验与报告不写回候选、历史标签、生产数据库或浏览器存储，不连接网络或模型，不触发付费调用。
