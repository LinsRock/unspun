## 来源观察的待固定条件

首轮路径范围沿用 R1 任务板第 3 节。00B 按每个精确栏目 ID 登记以下项目，16 保存实际观察记录；RSSHub/源站版本变化后应重新评估受影响路径。

1. 采集周期、缓存周期及冷/热读定义；时间戳、客户端、目标等价资源和版本。
2. 跨缓存周期、跨日且符合该栏目的发布周期的窗口；深读、书评不按“每天必须更新”评失败。当前没有固定天数或容错率。
3. HTTP 与业务码、条目 ID、真实新增 URL/原始时间；缓存 200 和重复旧条目不算新鲜发现。
4. 作者/发布方、时间依据、材料范围、正文/预览与访问失败；每条路径按观察、材料处理、发布分别通过。
5. 失败/恢复、退避与单位资源；R0 单次成功和旧日志保留为历史证据，不扩写成本轮连续成功。
6. owner 交接、隔离、预算和可回退配置；普通部署始终不恢复旧 AI worker。

来源观察窗口与容错尚未冻结，G2 不满足。微信、小红书继续后续；知乎回答、实际媒体内容、重要领域和受限平台缺口继续保留，不用综合媒体条数抵消。

## 补样与留出安排

- 现有 43 项用于材料边界和回归，已参与原型组织，不申报独立留出。
- 00B 在 09/12 调整规则前补采真实、未参与提示/参数调试的条目，固定原 URL、时间、材料范围、内容指纹及收集时间；按文章、预览、视频简介、问题、旧文与重复边界核对必要覆盖。留出不足须如实记为技术未就绪。
- 调试集与留出集成员提前固定，留出只做技术验收。后续若查看留出错误并据此调整规则，该批转为回归，新版本另补留出，不继续称独立。
- 不强求付费全文、社区回答或字幕来完成简介入口；未取得这些材料时，对应能力和技术结论保持缺口。必要补样失败时先推进 01–08/11 等不依赖 G1 的任务。
- 旧事件排序严格回归与旧生成质量输入继续保留，不能用新基准删除原来的失败或把旧集通过解释为新内容质量通过。

## 成本统计口径

本轮没有模型调用，不能据此推算新版运行单价。既有每月 $20–50 是预算范围；具体实际执行上限、评测额度和阶段预留由 04 在该范围内登记并隔离，登记前不启动付费处理。grounding 的 $0.40/24h 仍是附加限制，不能当全站上限。

| 口径 | 分子与分母 |
| --- | --- |
| 每百候选 | 同窗口发现的去重内容对象为分母，保留被过滤和材料失败对象；对应任务链已知实付总额 / 候选数 × 100。来源观测不重复当内容数 |
| 每入选内容 | 同批准入后可发布的规范内容数为分母；卡片生成/审核/失败和重试等对应已知实付总额为分子，未入选尝试不能从费用中消失 |
| 每新导读 | 同窗口新增合格导读版本数为分母；对应生成、审核及失败/重试已知实付总额为分子；复用命中次数另列，不反复计为新生成 |
| 运行总额 | 账本中每个实际物理调用只计一次，覆盖 legacy/R1、embedding 与内部重试；充值与调用不双计，预算预留不记已发生费用 |
| 未知费用 | `usage_unknown`、缺 provider 费用、未结预留分别列笔数/金额和待对账原因，不填零；已知总额明确是下界 |
| 月度投影 | 16/17 根据实际候选量、入选率、导读请求/复用和物理调用成本给范围，注明日期、路径与模型；当前阶段尚未运行，投影为未测 |

分母为 0 的单价记未测，不记零成本。详细调用关联和独立提交账务由 04 实现，本登记报告不冒充已经覆盖该机制。
