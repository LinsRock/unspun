## 入口与尚缺证据

在 `server/` 下执行 `.venv/bin/python -m unspun.evaluation.member_selection_execution prepare`，只读已暴露登记并输出准备状态，不读取配置/凭据或数据库，不写文件。`preflight --review <path> --authorization <path>` 只做离线绑定检查；不等于账本已对账。

`run --phase exposed` / `run --phase challenge` 仍需要同时提供 `--review` 和 `--authorization`，且必须满足以下真实条件。没有创建这些证明或宽松跳过的命令：

1. **真实提供方逐笔凭证**：保存的提供方响应 `data.id` 必须为 `gen-1792567035-xqUccUdgq5n1RaXx5duo`，并有真实 `total_cost`。404、余额变化和零差额不算凭证。
2. **另行获准的对账**：外部对账授权记录必须绑定 request_id、凭证 SHA、用户原指令；随后通过既有机制实际对账。入口只核对原账本中的 reconciliation、usage、原 reservation/response、139 笔历史计数/费用及原七笔 hold，绝不自行对账。仅有凭证还不能运行。
3. **独立审阅证明**：`r206-selection-entry-review-v1` 绑定 `execution_fingerprint`、审阅人/时间、真实审阅证据、完整 source_freeze、逐笔凭证和对账授权的路径/SHA，并实际确认源代码、挑战期待、PR/main CI、部署成员源码一致、生产关闭及凭证来源。仓库中的 source-freeze 是待审快照，不是审阅完成证明。
4. **单独明确付费授权**：`r206-selection-paid-authorization-v1` 绑定相同 execution、审阅 SHA、提供方凭证 SHA、真实用户指令路径/SHA、授权人/截止时间及具体阶段；动作必须是 `run_registered_phases_once`，额度为同池 $0.30/原总额 $1.50，并明确允许该阶段的一次 account GET。旧提额、免费 requery 或对账授权均不自动成为付费授权。

具体字段由 `require_authority()` 校验，未提供任何预填“通过”的授权样板。文件 SHA 仅证明绑定，真实来源须由独立审阅人核实。运行仅接受显式原本机评测库 `unspun_quality_r1_20261016`，且策略/阶段额度仍符合旧登记；它不接触生产库。真实密钥须在上述证据完整后另行提供，入口没有凭据获取工具。

`report` 不需要仍有效的付费授权，也不读取密钥设置；必须已有与本登记绑定的首次运行文件，并显式设置原本机评测库 `UNSPUN_DATABASE_URL`。数据库事务强制只读。`--findings` 可读取独立完整依据审阅，要求 execution、首次输出 SHA、审阅人/时间及每个实际 applied 决定的 finding 完整对应；未提供时严格覆盖不给语义信用。报告不会读取或准备新盲，也不会自动恢复停止的阶段。
