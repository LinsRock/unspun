## 本地重启

需保留已经初始化的 `unspun_preview_m3b` 本地数据库。在 `server/`：

```sh
UNSPUN_DATABASE_URL=postgresql+psycopg://unspun:unspun@localhost:5432/unspun_preview_m3b \
  uv run uvicorn unspun.evaluation.preview_feed:app --host 127.0.0.1 --port 8013
```

在 `web/`：

```sh
UNSPUN_DEV_API_URL=http://127.0.0.1:8013 VITE_M3B_PREVIEW=true \
  pnpm dev --host 127.0.0.1 --port 5178 --strictPort
```

另建空的 `unspun_preview_*` 本地库并通过Alembic迁移后，可用 `python -m unspun.evaluation.preview_feed --seed` 复制这些固定案例；预览入口拒绝非本地/非preview库，也拒绝向非空库重复seed。不要把预览时钟/演示数据带入生产。

## 数据与上线边界

增量迁移只新增字段，不捏造旧文章的原文时间：旧生产数据原文时间/正文来源仍未知，需C2受控核实后才能进入有严格日期的范围。新采集仅在原文元数据可核实时记录报道时间；页面“全部”可查看未知材料。本预览使用已核实的40例，所以不能把它当成整库历史回填完成。

执行中初次迁移误用了本地开发库 `unspun`，未触及生产；随后用同一增量迁移定义的Alembic Operations补齐缺失的content_basis字段，版本与最终000009一致，未删除/覆盖原数据。测试用独立 `unspun_m3b_migration_test` 从000008升级核实旧时间保留；页面用另一独立preview库。
