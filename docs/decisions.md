## D-015 · 2026-10-12 · 后台覆盖历史查询与全部成本，配置 PR 与临时覆盖并行

用户逐项确认后台默认总览，包含费用、信息源、文章与事件、运行与任务、配置与操作记录。费用纳入 VPS/域名等，周期账目与站内续费提醒；区分期间成本、实际支出与预计费用，模型充值和调用不双计。信息源排序可切换，默认异常优先。聚类纠正纳入后续操作版，预览影响且不改旧日报。手动任务默认遵守预算，额外费用按次授权并记录。长期配置走 PR 与部署，紧急停源/暂停付费处理走可追踪、有到期或解除机制的临时覆盖；账务直接存数据库。分子项目实施，不将讨论确认视为功能已交付。完整方案见 `docs/superpowers/specs/2026-10-12-admin-workspace-design.md`。

## D-014 · 2026-10-12 · 实时事件流默认最新事件，报道时间与处理时间分开

用户试用发现固定事件长期占据前排，确认支持多种排序并默认打开“最新事件”。最早报道时间取事件所属来源文章中最早的有效发布时间，不使用入库时间或系统 `first_seen_at`；最新事件按此时间倒序，重复报道不使旧事件重新置顶。首批提供最新事件、当前热度、重要优先，记住用户上次选择；最新进展需有独立的实质进展识别，不以新增来源或 `changed_at` 替代。时间范围与排序分开，缺失/异常发布时间明确标注。M3 实现，具体热度公式、时间回退与进展识别在实施设计和评测中确定；当前代码与日报快照不随本条记录改变。完整产品口径见 `docs/requirement.md`“实时事件流的时间与排序”。

## D-013 · 2026-10-10 · 摘要与观点使用原文证据、差异分类及固定评测

T10 发现短正文摘要扩写、年份幻觉和将时间/行动阶段差异误判为冲突。用户批准先增强证据约束与评测，保留 D-004/D-011 模型档位；D-011 输入补充明确发布时间、已验证事实及有限原文片段，不将旧摘要视为事实证据。保存摘要引用，观点每条说法绑定原文片段，差异分五种，允许证据不足。指纹覆盖输入内容和生成版本。固定案例比较修改前后真实输出并记录保留信息/成本；引用匹配不能代替语义验收。30 案例真实评测后补充同一现有 flash 模型的语义审核：摘要生成仍为 flash-lite，标题和事实合并一次 flash 审核；观点生成后一次 flash 审核。增加调用与费用按 D-007 记录，不新增 pro 档；预算按实际调用计，观点每轮配置控制事件尝试数。真实评测费用要求新增审核受滚动 24 小时 $0.40 限额约束；额度不足展示原始标题并标未完成审核，观点停止生成并等待额度恢复，不把未经审核文本标成已验证。单次审核可修复译义和恢复遗漏事实，修正逐条再校验。受控重生成只修受影响事件，不改历史日报，不直接手改生产数据。

## D-012 · 2026-10-10 · 页面改动必须本地体验验收后才能提 PR

用户要求：以后凡涉及页面开发或修改，AI 必须启动本地服务器，提供可访问的预览地址和体验验收步骤；用户实际体验并明确验收通过后，才能创建 PR。自动化测试、截图或 AI 自检不能替代用户体验验收。本规则适用于所有后续里程碑，并写入根目录 `CLAUDE.md` 的 Workflow。纯后端任务仍按原有测试、评审和 PR 流程执行。

## D-011 · 2026-10-09 · 观点对比：flash 模型 + 摘要输入起步

需求文档写观点对比用"强模型"，但 M1 实测 importance（flash 档）已占日花费约 2/3，pro 档 + 全文输入估计每月多 $20–40，容易顶破预算。M2 起步方案：输入用各来源的中文摘要 + 标题 + 导语（付费墙源本就只有导语，全文输入对它们不成立）；模型默认 `google/gemini-2.5-flash`（`UNSPUN_VIEWPOINT_MODEL` 可覆盖）；只对满足多样性门槛（≥3 个独立来源且跨 ≥2 个地区或类型，常数在 `config/scoring.yml`）且文章构成有实质变化（输入指纹变化）的事件生成。试运行抽查质量不足再升级 pro 或全文输入，升级时更新本条。

## D-010 · 2026-10-09 · 客观信号分改为对数饱和 + 单语言单地区折扣

初版线性计分（20 分/源、20 分/篇近 24h 文章，5 个即满分）在试运行中让大量只有本地热度的事件广度、增长双满分：饱和点太低、广度与增长双重计数、跨语言/地区只是小加分压不住单语言扎堆。修订（见需求文档"客观信号分细则"）：来源数与近窗新增文章数改对数饱和（cap 默认 15/10）；单语言且单地区的事件广度乘 0.7；增长口径从 fetched_at 改为 published_at；常数全部进 `config/scoring.yml`。定位不变：全球 vs 本地的主判断由 LLM 重要性分的 scope 维度承担（权重 0.45），客观分只衡量源列表内的报道面。不做历史事件全量重评（重评会重新调用 LLM 产生费用），新公式随事件下次内容变化自然生效。

## D-009 · 2026-10-09 · 前端外链只放行 http(s) 协议

事件卡片的原文链接来自外部抓取的 RSS 源，属不受信输入。`EventCard.tsx` 的 `safeHref` 只放行 `http:`/`https:`，其余不渲染为链接，防止恶意源用 `javascript:` URI 注入脚本。配套：抓取入库侧也应校验 URL 协议（见 M1 任务板 A6），前后端双层防御。

## D-008 · 2026-10-09 · 无官方 RSS 的中文源推迟到 M2

财新、澎湃、界面、联合早报、机器之心、36氪没有官方 RSS。M1 只用官方 RSS（28 源：22 英 6 中，已逐一验证可用），上述源等 M2 自建 RSSHub 后再接入。不在 M1 引入第三方镜像源，避免稳定性和合规风险。

## D-007 · 2026-10-09 · 每次 LLM 调用记账入库

`unspun.core.llm` 的每次调用把 token 用量与成本写入 `llm_usage` 表，日报据此汇总当日花费。理由：M1 验收有月度折算 ≤$50 的预算红线，花费必须随时可观测，而不是月底对账单才发现超支。

## D-006 · 2026-10-09 · 日常调参只改 config/，不改代码

聚类相似度阈值（0.72）、排序时间衰减半衰期（24h）、评分权重等全部在 `config/scoring.yml`；源清单在 `config/sources.yml`。理由：调参是 M1 试运行期的高频操作，改配置不改代码意味着无需动测试和评审逻辑。

## D-005 · 2026-10-09 · 聚类采用增量最近质心 + 余弦相似度

每篇新文章与现有事件质心算余弦相似度，超过阈值并入最近事件，否则新建事件。理由：MVP 优先选最简单、可解释、可调参的方案；是否需要重聚类、事件合并/拆分，等 M1 试运行的真实数据说话，不提前过度设计。

## D-004 · 2026-10-09 · 模型分档：摘要用 flash-lite，重要性评分用 flash

摘要默认 `google/gemini-2.5-flash-lite`（量大、要求低、取最便宜档），重要性评分默认 `google/gemini-2.5-flash`（质量要求高一档）。均可用环境变量覆盖：`UNSPUN_SUMMARY_MODEL` / `UNSPUN_IMPORTANCE_MODEL` / `UNSPUN_EMBEDDING_MODEL`。

## D-003 · 2026-10-09 · embedding 用 qwen3-embedding-8b，MRL 截断到 1024 维

数据库 pgvector 列宽固定 1024 维；embedding 取 `qwen/qwen3-embedding-8b`（中英混合语料效果好、OpenRouter 可用、约 $0.01/M tokens），MRL 截断到 1024 维后做 L2 归一化。固定列宽的理由：换 embedding 模型时不必迁移表结构。

## D-002 · 2026-10-09 · LLM 与 embedding 全部走 OpenRouter

只维护一个 `OPENROUTER_API_KEY`，不接 OpenAI，不在 VPS（2核4G）本地跑任何模型。理由：单一账单与花费上限、模型可随时切换、小机器只做管道不做推理。

## D-001 · 2026-10-08 · 部署链路：CI 构建 → GHCR → SSH over Cloudflare Tunnel

镜像由 CI 构建并推 GHCR；部署用 cloudflared SSH（Access service token 认证）进 VPS 执行 `deploy/deploy.sh`。VPS 不开放任何入站端口，Web 仅经 Tunnel + Access 暴露，生产密钥只存在于 VPS 的 `~/unspun/.env`。
