# M3-A4 周期费用账目实施计划

**目标：** 为 A5 提供可审计的固定费用、充值、付款、汇率和期间成本数据基础。

**边界：** 本 PR 只交付模型、迁移、服务层和写入 API；费用图表与查询页面在 A5。所有金额用 Decimal，日期采用北京时间自然日，覆盖区间左闭右开。

## 1. 数据模型和迁移

- 增加 `expense_rules`、`expense_entries`、`fx_rates`、`expense_audit`。规则保留锚点日期、周期、当前版本和停用状态；账目复制生成时的名称、类别、金额、币种及规则版本。
- 规则与覆盖起点唯一，生成在事务内使用唯一约束防重。账目并发更新以 `version` 条件写入。审计存旧/新值、操作者和原因。
- 数据库约束检查正金额、币种、日期区间、状态/付款字段及规则周期。

## 2. 日期和成本算法

- 先写月末、闰日、跨年、部分区间与缺汇率测试，确认失败。
- 周期边界始终从原锚点计算；月末回退不会改变下一期锚点。按覆盖自然日精确分摊 Decimal，输出原币金额与可换算 USD 金额。未付款覆盖期单列预计成本；充值从期间成本排除。
- 汇率按有效日期查找当日或此前最新记录。缺失时只返回原币及未换算标记，不假设 1:1。

## 3. 写入服务和 API

- 先写数据库/API 失败测试，再实现创建与修订规则、限定日期幂等生成、手工账目/充值、付款确认、取消未付款账目、汇率创建或修订。
- 写 API 校验 Cloudflare Access 身份与同源请求；金额、日期、版本及原因输入校验。每次成功写入同时存审计；并发冲突返回 409。
- 提供单项读取及区间成本计算接口供 A5 复用。API 不触发外部付款。

## 4. 验证

- 执行 Alembic upgrade、数据库测试、完整 `ruff check`、`ruff format --check`、`pyright`、`pytest`；核对迁移与 ORM 一致。
- 更新 M3 任务板的 A4 实施证据。A4 没有新页面，D-012 页面体验门槛在 A5 应用。
