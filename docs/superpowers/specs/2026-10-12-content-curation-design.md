# 精选、事件进展与出版产品架构

日期：2026-10-12。状态：用户确认产品方向并要求更新需求与开发路线；本文记录产品与架构边界，尚未实施。用户随后决定结束 M2 并开启 M3，任务板见 `docs/tasks/m3.md`；各实施子项目仍需分别完成数据设计、评测基线、任务拆分及验收。

## 目标与取舍

让用户用几分钟理解值得关注的变化、依据与不确定性，同时拓宽领域、来源和观点。对比其他日报产品得到的启发是采集、收录、精选和出版分层，不复制其垂直 AI 内容范围或信源数量目标。

选择先完善精选与事件进展：优先扩源会增加重复处理和运维成本；优先周月报或分发会延续当前选材问题。已有后台与事件流体验继续先行，为后续内容决策提供可观测性和干预能力。

## 当前基线

- 本地配置 63 源；worker 默认统一 30 分钟串行轮询，循环中先检查日报，再抓取和处理。未复查生产运行数据。
- 文章先摘要再 embedding、聚类和评分。已有证据约束与语义审核；没有独立的精选准入记录、转载出处识别或实质进展实体。
- 事件新增文章会更新 `changed_at`；日报用该时间筛选近 24 小时事件并取衰减分前十，LLM 只写导语。社区分仅表示是否包含社区来源。
- 日报已有快照、历史查询和已加载内容的离线阅读；周月报、完整破圈与外部推送未实现。M2 剩余验收沿用原记录。

## 职责与数据边界

| 单元 | 输入与产出 | 边界 |
| --- | --- | --- |
| 采集留存 | 来源配置 → 有效条目、可得正文/导语、时间与抓取状态 | 提取失败保留元数据，重复正文可复用但保留观测关系 |
| 用途与重复识别 | 原始材料 → 事实/观点/信号用途、指纹与明确转载出处 | 用途可组合、按条目校正；未知出处不推定独立 |
| 证据处理与归并 | 材料 → 证据约束的摘要、事件及引用 | 复用当前摘要/embedding 顺序，替代方案必须先评测 |
| 内容准入 | 事件及其材料 → 候选、拒绝或待判定及理由 | 不以热度或多来源数量作为硬准入条件，不把审核延期当拒绝 |
| 实质进展 | 事件及新旧证据 → 有归属与时间的变化记录 | 区分转载、背景、观点和实质变化；纠错/撤回可产生进展 |
| 排序与本期选编 | 合格事件/进展、历史入选记录 → 排序与入选理由 | 高分不自动入选；兼顾新意、多样性和阅读负担 |
| 出版与投递 | 选编结果 → 固定期号快照 → 可选外部投递 | 发布与发送状态分开，失败可重试且防重，已发布快照不回写 |

热度观测作为关联事件的独立输入，记录平台、指标、观测时间及关联依据。不同平台原始数值不直接相加，缺失不计零。先落地可追溯数据，完整归一化在有真实观测后评测。明确转载同一原始材料的多站报道不重复计为独立证据。

## 用户可见行为

事件流仍默认最新事件，新增“最新进展”和“读后有进展”须等待进展能力；系统处理时间不能冒充报道时间。事件时间线说明具体新增什么及其证据，无法判定时保留不确定性。

日报最多 10 条，不为凑数放宽质量；编排覆盖重要变化、持续事件进展与拓宽视野。重复报道不重新占位，重要背景或新观点的再次入选说明理由。初期提供领域与来源多样性，完整约 20% 破圈规则随兴趣与破圈子项目接入；候选不足如实说明。

默认北京时间 08:00 出版，日报窗口固定为前一天 08:00 至当天 08:00，左闭右开；迟到补生成仍使用固定窗口。记录实际发布完成时间和材料缺失，迟到材料可在后续一期标明补收录，不改变旧快照。周报覆盖上一个自然周，周一 08:00 发布；月报覆盖上一个自然月，每月 1 日 08:00 发布。周月报回看完整事件与进展库，不仅压缩日报。

可选飞书投递在报告稳定后独立交付，默认关闭；仅在目标明确且启用后从已发布快照投递少量条目与站内链接，按期号/目标防重，维持 Access 访问边界。

## 调度、预算与恢复

复用 Postgres、worker、FastAPI 和现有前端。按源采集、付费处理、出版各自有可恢复任务状态和独立调度，后台手动任务共用去重、并发互斥、预算与审计能力。慢源和长处理不阻塞出版截止检查；不足材料如实标注。先用配置周期与失败退避，贡献驱动的自动调频在后续真实观测基础上设计。

不新增消息中间件或微服务；在 M3-C 确定任务表、领取/锁定、重启恢复及预算预留设计，在 M3-F 确定提前准备、截止和快照发布策略。现有模型档位、费用记账、审核限额沿用，新增阶段不能隐式提高预算。未完成审核不标已验证，任务失败不丢失已发生的调用费用。

数据通过增量迁移增加，当前条目和快照保留。历史没有准入、进展和观测记录的部分明确未记录，不自动追溯为已审核；需要补处理时使用受控、有预算的任务。已发布内容纠错通过后续进展或明确更正呈现。

## 开发顺序与验收

产品路线以 `docs/roadmaps.md` 为唯一排期来源：M2 收尾 → M3-A 后台查询 → B 排序与已读 → C 后台操作/任务调度 → D 精选准入 → E 实质进展 → F 日报编排 → G 兴趣与破圈 → M4 周月报与可选分发。M5 经典库和 M6 扩源保持。

开工时固定各阶段样本、标注口径、基线与阈值，验证内容误杀、重要事件漏选、无进展重复、证据充分程度、多样性和成本；既抽查入选内容，也抽查被排除内容。样本包含推广中的有效事实、单源成果、小众评论、重复转载、同主体不同事件、纠错、缺失时间与迟到材料。不得用模型自评替代真实阅读反馈。

调度和出版验证故障、预算不足、重启、并发、跨日边界、补期及防重；F 上线后重新观察七天出版表现。评分/提示词变更通过固定评测，页面变更依 D-012 本地体验验收。各子项目独立交付，不提前编写跨全部子系统的代码级大计划，也不在本次文档变更中发消息、启用推送或修改生产。
