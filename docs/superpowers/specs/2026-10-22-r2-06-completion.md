## 后台最小路径

复用现有认证、同源校验、TopicMutation 的 CAS/幂等审计，以及现有材料/成员/派生有效性校验，不增表。新增 `/admin/topics`：查看事件/议题、成员与原文依据；人工建立话题、补充/修正/移除成员；查看修订前后、操作者和原因；从成员判断进入真实任务、审核和逐笔费用。人工修正明确标记 `r2-member-manual-v1`，不伪装成模型结果或质量评测成绩。修正后原派生通过现有依赖指纹即时失效，旧版本保留，不自动生成重算任务或调用模型。

API 均在 `/api/admin` 认证下；写入还要求同源 Origin。actor 从认证身份取得，客户端不得指定。写入必填 mutation_id、expected_revision、reason；同一操作重复提交复用原收据，旧 revision/改变同一操作内容返回 409，错误归属/非当前合格材料返回 422。写入事务独立于只读 GET；不从浏览器接收任意内部 TopicMutation 操作。

- `GET /topics?q=&status=&page=1&page_size=20`：`items`（id/kind/title/domains/status/revision/active_member_count）、total/page/page_size/processing_enabled。
- `POST /topics`：topic_id、mutation_id、reason、kind、title、domains；固定 expected_revision=0，创建人工话题。响应 topic_id/revision/mutation_id。
- `GET /topics/{id}?member_page=1&history_page=1`：topic；members（article_id/title/url/source_id/material_id/active/relation/basis/decision_version/evidence/check）；members_total/member_page/page_size；changes（revision/mutation_id/actor/reason/command/before/after/recorded_at）、changes_total/history_page；updates/derivations 的保留版本与实时 check，明确数量上限；topic 相关任务从独立 tasks 接口查询。
- `GET /member-contents/{article_id}`：当前规范 article_id/title/url/source_id/material_id/scope 与 paragraphs（index/text/voice/allowed_voices）；不合格或过时材料不能用于保存。问题背景和媒介描述限定相应 voice，其他 scope 的 voice 为 null，由操作者按原文明确选择，不默认报道。新增成员的关系也必须明确选择；编辑保留原关系/合法 voice。UI 选择原文段落、范围和关系，不借用另一材料。
- `POST /topics/{id}/members`：mutation_id/expected_revision/reason/article_id/material_id/relation/basis/evidence（article_id/material_id/paragraph/quote/voice）。复用 SetMember；decision_version 服务端固定人工版本。
- `POST /topics/{id}/members/{article_id}/remove`：mutation_id/expected_revision/reason。保留旧成员记录及修订。
- `GET /member-tasks?topic_id=&article_id=&status=&page=1&page_size=20`：仅真实 topic_recall/topic_judge/topic_review 任务及分页，不提供重启按钮。
- `GET /member-tasks/{id}`：task、attempts、judgments（原 decision/review/状态）、calls（物理 ID/阶段/状态/已知费用/未知全额预留/任务及 attempt/provider ID）、全任务费用汇总与记录上限。未知费用不补零；GET 不触发模型或重签旧审核。

页面复用现有后台布局与中文文案，冲突提示要求刷新后重新审阅；刷新丢弃过时编辑，网络失败保持同一个 mutation_id 以便幂等提交。先完成真实 API 本地预览和关键交互检查，再依 D-012 取得用户页面认可后提页面 PR。该认可只验收人工后台，不代表模型质量通过。
