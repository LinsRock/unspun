# R2-02 扫描与处理配额

基线 `d4df296`；本批仅实现 R2-02。旧 `max_items` 继续限制 legacy 采集；未配置 `r1.quotas` 的 R1 路径保持原行为。显式配置后，`scan`（1–200）限制一次响应内检查的条目，`material`、`paid`（0–200）分别限制一次调度发现所分配的材料任务与新卡片处理任务，`recheck_seconds`（60–2592000，默认 86400）控制无元数据变化的已知对象复查间隔。它不是 HTTP 重试次数或新的美元额度。

当前八路启用 `scan=30`；七路 `material=paid=1`、BBC World `material=paid=30`，原来源、材料/发布范围、周期、模型和预算保持。最大扫描槽由 144/日变为 2580/日，材料与新卡片逻辑槽仍最多 144/日（七路×12＋BBC×2×30）。RSS/原站列表请求数不随扫描条数增加；人民日报仍为目录与头版两次，知乎日报仍一次列表。RSSHub 冷缓存可能在其内部请求更多条目，但本批不增加路由请求、分页或正文预取；响应边界仍 2 MiB，原超时/退避保留。

先保存有界元数据、识别规范 URL/平台身份与批内重复，再做与既有时效一致的轻量排除。材料未取的候选按首次发现时间排队；需要复查的已知对象按最近一次材料任务时间轮转，有未处理候选时先保留一个复查机会，余下槽用于未处理候选；仅有一个槽且两队列都等待时按已提交收据交替，防止两方饥饿。元数据变化可触发复查；未变化的活跃/待重试材料任务直接复用。扫描范围外的更新与不再出现的对象不保证可复查。

新 `discovery_batches` 表以来源和调度任务 ID 唯一保存配额、观察时间、扫描前后/有效/重复/新旧身份计数、选择理由及任务 ID；调度重试使用同一 ID，提交重放返回原收据。选择在短事务内序列化，不持有网络事务；材料后继和配额同事务提交。付费槽在材料合格后分配，同处理指纹的已有任务不再消耗新槽，延期/重试继续原任务与账务。扫描到已有合格材料时，也可分配尚未获得付费槽的卡片，不要求再次请求正文。导读仍走原显式请求与预算，不属于自动卡片槽。

计数版本为 `r2-discovery-v2`；扫描前表示适配器声明容器中的条目/链接数，不冒充全站发现量。批内身份重复、跨轮已见、材料选择、新付费任务和实际提供方请求使用不同分母。历史数据不迁移、不补计数；R2-01/v1 冻结哈希和用户空评分保持。

回退可去掉 `r1.quotas` 恢复原 `max_items` 扫描/入队行为；已建任务、收据、材料、费用和未知预留保留。代码回退仍须通过 PR/部署，不降级删除表，不恢复旧 worker。实际请求量、费用场景和部署核对在本批验收报告补录；本地模型全部 mock，不新增付费评测。
