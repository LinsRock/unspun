# R2-05 话题、成员与版本最小契约

实现前固定于 `origin/main b5f812c`，本批只交付内部 Python 读写与校验、增量 schema 和恢复证据。R2-04 继续进行中，观察容器、挂载 worktree、原始证据与关闭来源配置保留；不接手来源启用。没有 embedding、语义归并、进展判断、模型调用、任务/账务新阶段、混合排序、公开接口/页面或生产回填。原来源、配额、模型、预算、冻结材料、空用户评分及未知费用不变。

## 数据职责

新增 `topics`（UUID 资源、event/issue、名称/领域、active/archived、单调 revision）、`topic_members`（话题与规范内容的多对多当前投影）、`topic_changes`（幂等收据与完整命令/前后状态）、`topic_updates`（按稳定 update UUID 追加的进展修订）、`topic_derivations`（overview/guide 的追加草稿版本）。主题词继续是 `reader_interests.kind=term`，不会变成话题 UUID；现有 card.topics、card/guide、反馈及 API 均不改。

规范内容是 R1 `articles` 别名链的根，最多解析 64 跳，缺失、legacy 或环路拒绝。写成员时可输入别名，但材料必须归属于解析后的根；成员键固定为根 ID，身份合并/拆分不静默迁移旧成员。身份快照包括根及递归别名的 URL、来源、平台身份与 URL 别名；新重复观测不改变身份快照。

关系枚举为 report/background/opinion/explanation/reprint，只是带依据的分类，不断言语义判断正确或独立报道数。成员保存当前材料 ID、材料/身份/来源/合格 card 输入快照、判断契约、文字依据、逐段引用及最后修改 revision。移除保留 inactive 行和历史；重新加入是新 revision。引用显式包含根 article_id、material_id、从 0 开始的段落索引、原文 quote 与 reported/author/question/description 归属；检查材料所有权、当前材料、精确片段和受限材料 voice，不能引用旧摘要或另一个内容的材料。数据库复合外键进一步保护成员材料归属。

## 时间、指纹与失效

进展仅保存调用方明确录入的修订，不实现判断。每条有稳定 update UUID、active/retracted、summary、引用及 occurred（发生）/reported（本材料报道）两个独立时间。time 需要带时区 timestamp 和引用内的文字依据；date 只保存日期和依据，unknown 不含日期/时间/依据；不从抓取、处理或新转载补造。处理时间仅是数据库 recorded_at/created_at，不参与发生/报道时间或排序。

成员快照复用现有当前合格内容校验，无推荐年龄限制。指纹覆盖规范身份及材料实际段落/范围/元数据/提取版本、现有 card 输入/审核版本，以及该材料来源的发布开关、发布范围与材料声明边界；无关来源、配额、重复观测不进入指纹。更改成员关系/依据也产生新成员 revision。成员校验失败时，引用该成员的进展失效；未引用该成员的进展保留。话题定义修订使进展失效。移除/重加或改回旧关系不恢复旧进展。

话题派生快照覆盖话题定义、全部 active 成员及其 revision/材料快照、所有进展的最新修订及有效性；任一成员或进展变化保守地使 overview/guide 失效。input_fingerprint 另外覆盖生成/审核契约与模型标识；不会修改或强制重生成 R1 card/guide。派生只保存 draft，逐项主张引用当前成员，不能当成语义审核通过或公开可用。每种派生和每个 update 的旧修订均标 superseded，不因值改回而成为当前版本。校验是无副作用的实时比较；材料/来源恢复到完全相同输入可恢复其动态可用性，但已产生的新成员/定义/进展修订及 superseded 永不回退。缓存或未来发布必须每次重新校验，不能只信历史布尔值。

## 写入与后续接线

单话题行锁串行化写入，expected_revision 做 CAS；(topic_id, mutation_id) 唯一，同 ID 同请求重放返回原收据，不再写入、不复活撤销结果；同 ID 不同请求拒绝。不同 ID 的同内容写入视为显式新修订。调用方控制事务提交/回滚；内部服务不发 HTTP、不创建 pipeline task、不花费。新增话题以调用方 UUID 幂等创建；跨话题独立锁。晚返回的派生写入必须携带原 expected_revision 和 input_fingerprint，当前依赖或契约变化即拒绝，不能把旧结果盖在新成员上。

R2-06 后续负责真实候选、判断、纠错及共享队列/账务阶段；R2-07 负责实质进展识别、中文/语义审核和公开资格；R2-08+ 另接排序、关注和页面。本底座不提供 ready/publish 状态，也不对生产种话题。旧 Event、旧摘要积压、日报、身份/反馈/账务及 legacy worker 退役状态保留。

## 迁移与保留数据恢复

`000018` 只新增五张表和约束/索引，不改旧行、不回填。downgrade 明确失败关闭，避免删除已写话题；部署回退优先保留 schema/数据、使用认识 `000018` 的固定镜像（具体测试范围在验收报告登记）。只有 `000017` 迁移目录的旧镜像在新库上无法解析 revision，不能直接用当前部署脚本切换成功，也不通过 stamp/删表伪装兼容。

隔离库验证从 `000017` 升级、重复升级、完整 pg_dump→新库 pg_restore、恢复后旧业务/账务及新历史逐表计数/散列一致、当前镜像重新读取与迁移。生产部署前保留备份入口并只读核对，生产不做 downgrade 或恢复演练。需要原 schema 的灾难恢复使用独立恢复库/卷与对应固定旧镜像，原升级后库及所有新增业务数据继续保留，切换前须另行核对写入差额，不能丢弃新数据来完成回退。
