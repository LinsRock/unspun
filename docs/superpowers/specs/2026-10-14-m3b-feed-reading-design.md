## 现状与证据

现有 `/api/events` 按 `score_final × 2^(-age(changed_at)/24h)` 排序，只返回前 50 条，卡片显示系统 `changed_at` 为“更新于”。新增转载会刷新该时间；晚抓旧闻也可能被视为新事件。没有事件流阅读状态。

本次只读查询已有开发数据集：1132 篇文章，1132 篇有发布时间，0 个事件。并非当前生产快照。保存 12 篇晚抓文章元数据至 [证据文件](../../feedback/m3b-evidence.json)。例如文章 1007 的 Swatch 广告争议：报道时间 2025-08-20 13:21 UTC，入库 2026-10-09 03:46 UTC；报道与入库相差超过一年。文章 1006 的猫癌症研究报道与入库也相差数月。没有依据认为旧时间本身异常。

另收集既有质量评测中的 5 个生产审计短摘录，仅能作为候选线索。摘录的发布时间没有为排序重新核实，不进入时间基线。不能将这些摘录或上述文章冒充 30–50 个已标注事件。

## 方案比较与建议

1. 推荐分两个交付：B1 固定报道时间契约、三种排序与分页；B2 增加跨设备阅读和偏好恢复。新热度公式先进行离线候选比较并接受人工排序判断，再接正式 API。符合任务板顺序且能单独定位排名与阅读问题。
2. 先只交付“最新事件”与阅读，保留旧排序作为兼容项。可以更早解决旧闻置顶，但不满足 B1 的三种排序完整范围；如采用，须明确改任务拆分，不勾选 B1 完成。
3. 直接用现有客观分当热度，换 `changed_at` 为最新报道时间。修改量较少，但客观分包含历史广度、来源质量，评分仅在内容变化时更新，也存在缺失发布时间回退到抓取时间的旧逻辑，不等同于当前报道活动，不推荐。

采用方案 1。不修改现有 LLM 提示、评分权重、聚类或日报选材/快照；排名专用指标与卡片已有综合分分开展示。新增热度排名依然属于排序变更，须过标准事件集门槛。

## B1 · 报道时间契约

每次请求固定 UTC `as_of`；所有窗口与排名使用同一时刻。有效报道时间的候选规则：`published_at` 非空，晚于或等于 1970-01-01 UTC，不晚于该文章 `fetched_at + 5 分钟`，并且不晚于 `as_of`。5 分钟是待评测的容差，不是已确认生产结论。很旧但可信的日期保持有效，不加“太老就算缺失”的截断。

按事件所属有效文章求最早、最新报道时间，并返回有效、缺失、异常文章数。范围中只计 `fetched_at <= as_of` 的已收录文章；没有有效时间的事件返回 `reported_at = null`，不能把 `first_seen_at` 或 `fetched_at` 填进报道字段。增补更早报道只会把最早时间前移，新增更晚转载不把最早时间后移。

无有效报道时间的事件仅出现在“全部”的末尾“报道时间未知”分组，组内按首次发现时间倒序、事件 ID 倒序。今天/24 小时/7 天不推断这些事件属于时间窗口。卡片注明“报道时间未知 · 首次发现 …”；混合有效与异常时间显示有效报道时间并附“部分来源时间异常/缺失”。

这是基于元数据的异常检查，无法证明所有看似正常的年份准确。后续用户反馈可增加固定回归案例，不静默改既有口径。

## B1 · 时间范围与排序

首次访问默认“最新事件 / 最近 7 天”。范围独立选择：北京时间今天、最近 24 小时、最近 7 天、全部；切换排序保留范围。所有有效窗口为 `[start, as_of]`，请求端点恰好等于 `as_of` 的报道纳入当前查询，下一页固定同一 `as_of`。

| 排序 | 范围依据 | 排序键 | 页面说明 |
| --- | --- | --- | --- |
| 最新事件 | 最早有效报道时间 | 最早报道时间倒序、ID 倒序 | 按最早报道时间；新增转载不会刷新事件时间 |
| 当前热度 | 窗口内存在有效报道；全部也只使用最近 24h 活动 | 候选热度倒序、最新有效报道时间倒序、ID 倒序 | 近期来源报道活动，不代表独立事实证据或实质进展 |
| 重要优先 | 最早有效报道时间 | 已有 `score_final` 倒序、最早报道时间倒序、ID 倒序 | 综合分：现有重要性与客观信号，范围按最早报道时间 |

重要优先复用现有综合分，不另加时间衰减；缺分事件放已评分事件之后并标“尚未评分”。卡片徽标仍是原有综合分，不显示为热度分。热度模式额外给出来源活动数、候选热度与有效窗口。最新事件排序不依赖是否已评分。

今天从北京时间当日 00:00 起；最近 24h 从 `as_of - 24h` 起；最近 7 天从 `as_of - 168h` 起。“全部”对最新事件/重要优先没有下限。午夜附近两者自然产生不同结果，页面明确显示窗口起止与北京时间。

## B1 · 热度候选、证据边界与评测

推荐先评测一个可解释的活动指标。对所选范围中的有效报道，按配置来源分组，每组只取窗口内最早一次报道时间 `t_s`。同来源重复文章不提高贡献，也不因后来重复文章刷新衰减时钟。固定最近 6h 的新来源活动体现增长，24h 半衰期体现衰减。

```text
activity = sum(2 ** (-(as_of - t_s).hours / 24))
growth = count(source groups whose t_s >= as_of - 6 hours)
heat = activity + 0.5 * growth
```

今天/24h/7 天按选定窗口取 `t_s`；全部按最近 24h 取 `t_s`。因此切换范围会改变热度值，不只是改变候选列表；页面显示“窗口内来源活动”。0 活动的有时间事件不进入热度列表；无有效报道时间的事件在“全部”独立未知组末尾保留。

该公式与 6h/24h/0.5 均为候选，不能先实现上线再补调样本。基线同时比较旧 `changed_at` 衰减排序、无增长奖励的来源衰减排序与上述候选。固定输入、`as_of`、参数、来源配置和版本哈希；不额外调用模型或重写存储分数。

现有配置来源 ID 并不等于独立媒体或独立证据：同一媒体的多个栏目可重复计数，不同媒体可能转载同一稿件。在评测输入中人工确认同媒体分组并合并其栏目；直接媒体可按来源默认分组，HN等聚合入口需逐文章出版方覆盖。映射保存为版本化配置，不能靠域名相异自动断言独立性。已知转载在样本中记录其原始来源关系；未知关系保留未知。

B1 可交付“去重媒体来源活动”的明确代理指标，页面不用“独立证据数”措辞。完整转载关系由 M3-D1 提供；在此之前不能保证完全消除跨媒体转载对热度的贡献。旧事件新增转载可以表现为报道活动，但不回到最新事件前排、不生成实质进展、不撤销已读。这个证据边界需用户在设计审阅时确认。

评测要求：人工标准事件集 30–50 个、覆盖领域与档位；补入晚抓、同源重复、多栏目、已知转载、缺失/异常时间、少报道但重要的案例。人工标注“值得读”、重要性档位、三个排序的合理优先关系和媒体分组。必过规则：旧闻不算当前活动、同媒体重复不涨分、旧事件新增报道不刷新最早时间、北京时间边界正确，全部通过；用户标注的明确排序对不得颠倒。没有明确偏好的事件不强造总顺序。候选未过则保留失败报告，重新讨论公式，不在验收前调整期望迁就结果。

标准集版本与人工作者审阅记录固定后接 CI；未标注或未冻结时 CI 明确拒绝将评测标为通过。现有 30 个内容质量回归样本不是这一标准集。

## B1 · API 与分页

`GET /api/events` 白名单：`sort=newest|hot|important`、`range=today|24h|7d|all`、`limit=1..100`、`cursor`。默认 `newest/7d`；无效参数返回 422。返回 `as_of`、窗口、排序说明、`next_cursor`，每条增加最早/最新报道时间、时间状态、排名指标。旧 `score_decayed` 字段保留可空兼容，但不作为新排序解释。

分页使用固定 `as_of` 的复合键游标，带排序、范围、版本与上一条排序键；换条件重开第一页。游标解析严格限制长度、值域与匹配条件，同值用事件 ID 决胜。查询由数据库聚合排序，不抓前 50 条在前端再排序或筛选。

固定 `as_of` 排除后来抓到的文章，避免正常采集造成跨页漂移。它不是跨任意聚类纠正或重评分的数据库历史快照：B1 要覆盖静态数据、同分分页和正常新文章采集；并发重评分/重聚类须令页面重开第一页，客户端仍按 ID 去重。C2 受控纠正接入时增加明确的失效信号。若要求任意写操作期间仍绝对冻结排名，需要另做排名快照持久化，本轮不冒充已具备此能力。

## B2 · 跨设备阅读状态

单用户状态保存在 Postgres `event_read_states`，事件 ID 为主键/外键（事件删除级联），字段 `is_read`、`read_at`、`version`。未有记录即未读。仅显式点击“标为已读/标为未读”改变状态，滚动、加载、展开分数或来源不自动标已读。设置已读记录服务端时刻，改未读清空 `read_at`；普通新增文章不改变阅读状态。

`GET /api/events` 增加 `unread_only=true|false`，服务端在分页前筛选，不能只过滤当前已加载的 50 条。返回阅读状态和版本。

`PUT /api/events/{id}/read-state` 接收目标布尔状态与期望版本；事务内按版本更新。并发冲突返回 409 与最新状态，页面刷新该条，给出“阅读状态已在其他设备更新，请重试”。不存在事件返回 404；新增行竞争由唯一键保护。失败不显示成功，不离线排队；网络不可用时禁用写操作并提示。

读写状态接口复用网站 Cloudflare Access 的 JWT 验证能力；生产配置缺失拒绝访问，不接受浏览器随意传入身份。本地预览仅允许现有配置开关及 loopback。单用户全站共享一套状态；Access 的账号标识用于验证访问，不拆分成多用户产品。PUT 校验同源请求（Origin/Fetch Metadata），不扩大跨域策略。

## B2 · 偏好、URL 与缓存

排序/范围/只看未读保存到单用户 `feed_preferences` 单行记录，有版本；服务端保存使新设备可恢复选择。URL 显式参数优先，随后服务端偏好，随后本地最后成功同步偏好，最后默认值；服务端不可达才使用本地回退。显式 URL 浏览不会自动覆盖跨设备偏好，只有用户操作控件才保存。

偏好 API 验证白名单并带版本，冲突刷新后提示；服务端数据读取完成前不抢跑默认查询，避免先看到默认排名后跳动。浏览器前进/后退从 URL 恢复，保留其他合法路由参数；遇到非法流参数回退默认并显示可恢复提示。

TanStack Query 的 query key 包含排序、范围、未读条件。默认每 5 分钟刷新第一页，后台标签回到前台重新验证阅读状态；翻页使用本次 `as_of`。控件变化重置分页，服务端写成功才更新缓存；只看未读时，标已读后从列表移除并补请求。状态同步跨设备在刷新/轮询时生效，不宣称即时推送。事件流不加入现有离线日报 IndexedDB 缓存。

## 页面与阅读语义

沿用现有公开阅读页样式、亮暗主题、移动底部导航。标题下放排序控件、独立时间范围与只看未读；下一行显示排序依据、有效窗口、时间未知规则。卡片显示“最早报道 … / 最近报道 …”；系统处理时间独立折叠说明，不再写成新闻“更新于”。来源篇数与不同媒体数分开，不能将 `articles.length` 标成来源数。

卡片尾部显式阅读按钮和已读标识；不只靠降低透明度表达状态。无结果按当前过滤解释，提供“查看全部/关闭只看未读”；网络与认证错误可重试，不把失败显示为没有事件。分页用“加载更多”，400px/390px 无横向溢出，键盘焦点和屏幕阅读标签可用。

M3-B有效报道日期规则用于判断时间是否可信；“报道太旧”和“发布时间异常”分别处理，不改 epoch/5min 规则来掩盖旧闻。默认7天范围继续避免历史材料占据默认最新事件；它不等于所有新闻的内容有效期，也不能节省上游已发生的付费处理。

内容类型与当前有效性、昂贵处理前的低成本筛查纳入M3-D0/D1/D2：明显过期消息跳过后续付费与实时推荐；持续影响材料、知识/分析检查当前适用性；未知保留待判定。具体类型窗口、依据、例外与误杀/漏拦/费用验收在D0先固定，当前不新增统一7天硬删除规则或付费分类调用。历史元数据与日报快照保留。

准入能力上线后，“全部”只放宽报道时间范围，仍遵守内容准入与当前有效性；历史库由后台保留查询。本轮B1/B2尚不具备该准入过滤，也不声称已拦截付费处理。知识的独立阅读入口仍属M5。

保留样本里的过期新闻与旧知识，用于检查重要性、当前阅读价值和有效性边界。审阅表“现在是否值得读”独立填写；类型/当前有效性及依据先在备注记录，D0的数据设计再固定机器字段，不在本轮强行补造人工标签。实际打分动机由用户决定，不能把已给分数重新解释为纯粹不受时效影响的评分。
