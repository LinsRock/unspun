# Unspun 运营工作台重设计

## 1. 信息架构与模块调整
用户授权直接重设计正式后台。后台以采集 → 内容处理 → 事件组织 → 成本控制为业务主线。导航分为运营（运营总览、内容工作区、信息源、运行与任务、费用与预算）与系统（配置与审计）。沿用已有 URL 和 API 契约，页面名称与信息层级重新组织。阅读入口置于导航底部。

考虑过保留模块美化、独立 BI 仪表盘和运营工作台三个方案。选择运营工作台：BI 难以形成异常到对象的闭环，保留原布局无法解决主次不分的问题。

## 2. 核心页面布局与信息优先级
- 总览：横向指标带（文章、新建事件、已确认成本、抓取失败），异常工作带，主文章趋势与当前信息源健康，当前管线积压，用途费用分布与最近运行。时段指标与当前状态明确区分。处理状态趋势用于解释产出结构，不伪装成阶段吞吐漏斗。
- 内容：文章/事件标签 → 搜索、状态、排序 → 可展开更多筛选 → 结果数、已生效筛选 → 紧凑数据列表。标题可直接打开详情；选中当前页条目可批量导出。
- 信息源：当前配置与期间表现摘要 → 高频健康筛选 → 更多属性筛选 → 异常优先列表。成功率用数值和条形编码，产出数字不替代健康判断。
- 运行：历史与积压两个工作模式，当前积压按阶段切换与下钻；未接入的任务能力以说明呈现，避免空任务页占用主要导航。
- 费用：期间成本/实际支出切换 → 成本指标带与本月预算进度 → 趋势、用途与模型分布 → 调用、账目、续费工作模式。充值、分摊、支出维持原口径。
- 配置：运行节奏、模型路由、预算约束三组信息，凭证仅显示状态；信息源配置和审计为独立标签。当前部署配置只读，历史未记录须明确说明。

## 3. 图表与数据方案
文章趋势用面积趋势图，处理状态与调用用途趋势用堆叠柱图。健康用堆叠横条和可点击图例；成本用途用排序横条，模型用紧凑表格。颜色稳定区分成功、失败、待处理与未知；所有图提供数值、空态和按需展开的数据表。取消默认展开的整张趋势表，避免信息重复。
缺字段为未记录，零记录显示空态，不展示虚构环比、健康心跳、实时阶段和完成率。费用保留微额精度与缺汇率提醒。

## 4. 关键交互
全局搜索支持页面跳转和将关键词送入文章/事件查询；⌘/Ctrl K 打开，Esc 关闭。日期跨业务页保留；系统配置不受日期筛选。刷新重新取当前工作区查询并固定新的范围快照。更多筛选保留 URL 状态；生效条件可单项移除或全部重置，重置保留时间。详情抽屉维持列表上下文。列表选中项仅限当前页，切换条件不跨范围残留；批量导出仅导出选中真实记录，CSV 防公式注入。没有后端能力时不伪装启停、重试或预算写操作。

## 5. UI 视觉语言与组件规范
浅灰工作区与导航、白色内容面板、低饱和蓝色强调；暗色使用深蓝灰背景、稍亮面板与浅蓝强调，失败红与待处理琥珀。沿用系统中文字体；标题 28px，区块 15–17px，正文 13–14px，辅助信息 12px；指标采用等宽数字 30–34px。8px 间距基准，控件 34px，表格紧凑但保留双行信息。分隔线承担组织作用，面板圆角 8px，不使用成排大阴影卡片。焦点可见，状态同时给文字；图表不只依赖颜色。窄屏导航横排、指标 2 列、图区单列，宽表在局部滚动。支持已有暗色主题，样式只作用于后台。

## 6. 实施与验收边界
直接修改 web/src/admin 正式页面，不新增依赖，不改计费/评分/任务后端。完成构建与代码检查，启动本地真实 API 与页面预览，检查桌面、窄屏和主要查询交互。页面体验验收后再按 D-012 创建 PR；此次交付保留分支供审阅。

## 2026-10-14 用户体验反馈后的调整

1. 用户认为墨绿主题不好看、亮暗区别不明显：改为蓝灰配色，亮色导航为浅灰，暗色导航为深蓝灰，导航与内容都随主题变化。基础控件、抽屉、搜索与图表使用一致的主题色。
2. 内容、来源等单列表页面只保留页级标题与一段说明；内容面板直接从文章/事件标签与筛选开始。移除“内容索引”“采集网络”和重复描述。费用明细及账目标签也移除同名区块标题，图表等独立区块仍保留必要标题。
3. 信息源重排为上方统计区、下方筛选列表。统计分当前配置与所选期间表现：配置信息源数及启用数；至少成功一次的来源数、至少产生一篇新文章的来源数、至少失败一次的来源数。数字使用 33px，单位明确。统计随服务端筛选范围变化，标题明确显示全部来源或当前筛选结果，不把成功与失败当互斥类别求和。
4. 费用使用“使用成本 / 付款支出”的面向任务文案。总额不重复展示，分模型调用、已付款固定费用分摊与待付款费用分摊。日均与调用数一行呈现；计算口径、token 用量和原币明细收进说明。缺汇率保持显著提醒，仅在付款支出模式显示付款时间不完整的提示。
