# M2 内容质量优化设计

用户于 2026-10-10 批准“证据约束 + 分歧分类 + 固定样本评测”。保留摘要生成 flash-lite / 观点生成 flash。真实评测显示仅验证引用和轻量自审仍漏误译，因此增加使用现有 flash 档的语义审核，不引入 pro 或新模型档位；额外调用按 D-007 记账。此任务补齐 T10 内容质量缺口，不替代七天生产观察、手机实测与源数量决定。

## 摘要与共享证据

新增 Article.summary_grounding JSONB（可空、增量迁移），结构 `{version: "summary-grounded-v5", status: "grounded"|"limited"|"review_limited", facts: [{text, quote}], verification: {model, method}}`。LLM 输出 `{title_zh, facts:[{text,quote}], content_quality:"sufficient"|"limited"}`，不再要求固定句数。quote 必须来自传入的原文标题/正文，使用 Unicode 与空白归一后校验；不允许从旧摘要取得证据。不凭标题补机构、同比、因果或具体数字；少信息时允许零 facts。零有效事实使用原始标题作最小摘要并标为 limited，避免永久重试或写入编造摘要。摘要事实与翻译标题合并为一次 flash 语义审核，标题引用只取原始标题；拒绝的标题回退原文，审核无效时事实不落库。审核先给出逐条检查理由，再返回完整 corrected_facts（含 title/fact 角色），可恢复草稿遗漏的原文事实和修正译义；每条修正重新校验原文引用、年份、术语和限定词，标题只用原始标题引用，无效的单条修正不影响其他有效事实；针对未指明的失业/利率、直升机、波斯湾、当地时间、发射台和网站加入有限双语术语约束，拒绝来源没有的额外具体化。记录实际审核模型与方法。摘要、观点与审核调用采样 temperature=0，降低随机波动但不保证确定或正确。引用匹配和模型审核均不是正确性的形式证明，仍需独立语义评测。

`unspun.core.grounding` 提供 `normalize_text(text)`、`quote_in_source(quote, source)`、`supported_years(text, source)`、`article_source_text(article, max_chars=6000)`。年份校验只限制额外出现的四位年份，允许原文明示的历史年份；不将发布时间当成事件发生日期。summary_grounding 留存事实与引用，source text 是原始标题 + 正文而非 title_zh/summary_zh。

## 观点

输入包括每源原始标题、published_at、已验证事实及相关原文片段；旧摘要不进入生成提示，避免污染。摘要优先作为片段选择的线索，限制输入长度，不自动发送整篇全文。生成与同档 flash 审核各一次，审核可修复或删除不受支持的说法/类型；最终双重校验引用属于实际传入片段和对应原始文本，并应用相同术语约束。规划/提议阶段的引文不以事实冲突落库，保守归为不确定。观点版本 viewpoint-grounded-v3。每条说法 `{article_id, claim, evidence_quote}`，证据必须匹配对应源的实际传入片段；每种差异 `{point, claim_indexes, kind}`，kind 为 factual_conflict / viewpoint_difference / coverage_difference / temporal_update / uncertain。只有同一对象、时点、统计口径的互不相容陈述才称事实冲突；未提及、备选计划/最终决定、币种与时点变化必须保守处理。分歧的额外年份需得到关联来源支持。无足够证据时允许空比较，缓存不足结果防止每轮付费重试。

缓存指纹加入实际输入、来源名称、模型和生成版本，保持排序稳定。候选筛选必须能发现内容变化及旧生成版本；候选以热事件和轮转背景交错扫描，每轮至多检查 200 个候选、尝试配置数量的事件（当前 10）；该配置是事件尝试上限，不是原始供应商调用上限。每个非空观点最多生成/审核两次逻辑调用，供应商截断重试另计。旧观点按兼容 schema 读取，前端标出未附证据；新输出必须有证据。

## API 与界面

ArticleOut 新增可选 `content_quality: "grounded"|"limited"|"review_limited"|null`；ViewpointOut 新增可选 `status: str|null` 以展示审核暂停；ViewpointClaimOut 新增 `evidence_quote: str|null`；ViewpointDisagreementOut 新增 `kind: str|null`。旧日报未含这些字段时默认 null，historical API 不依赖原文重读。观点卡片/日报支持展开“原文依据”，标明五种差异类型；旧数据标明未附证据，有限输入显示“信息有限”。所有外链沿用 safeHref，布局遵守 T-D1，用户本地体验后再提 PR。

## 修复与评测

固定 30 个案例，包含本次五个生产样本与清楚标为合成的边界/正常对照。评测报告记录证据有效率、保留说法数量、标题/摘要/观点禁用断言、逐文章摘要信息保留、差异分类、失败与 LLM 成本；不用全拒绝策略取得通过。先运行离线坏输出回归，再对同一输入比较旧/新真实模型输出并进行语义复查。真实调用在隔离本地评测库按 D-007 记账，不写生产业务数据；密钥不写入文件/日志。

提供显式 event-id 的受控修复命令，默认 dry-run，列出将重生成的文章和事件；执行模式通过正常 LLM/DB 模块更新摘要、embeddings、事件中心/代表摘要、重评分与观点。旧日报快照不修改。执行失败必须保留调用费用，不留下部分修复的混合状态；生产执行待代码经 PR 合入后再操作，本会话仅本地演示/评测。


## 审核费用与回退

真实对照发现逐篇额外审核费用显著，沿用现有每月 $20–50 预算而不默默增加上线成本。`UNSPUN_GROUNDING_BUDGET_24H_USD` 默认 0.40，是仅新增 grounding 审核的滚动 24 小时限额（大约 $12/月），不是全站 LLM 总费用承诺；0 可停止审核。实际每次 grounding HTTP 请求及截断重试前检查最近记账和当前事务的待提交费用，预算只阻止后续请求，单次费用和并发请求可能稍有超额。

额度不足时摘要回退原始标题，保存 `review_limited` / `budget_fallback`，不把它当成模型失败反复重试；API 和界面明确显示“未完成审核”。观点预检不足时不调用生成模型，保存待审核空比较；额度恢复时该缓存可以重生成，候选优先稀少或未完成审核事件。未审核文章的完整补齐通过受控事件修复完成。受控修复遇到审核额度不足必须保留原业务数据，已产生费用仍提交。

网络重试若在已有付费响应后失败，摘要/观点保留账单，且不把传输失败计入内容失败上限。评测库显式临时提高该限额以完整测评，并仍受单次 CLI 金额/请求数上限控制；不是生产预算修改。

标题保底仅逐字使用当前原始标题，不复用旧 title_zh 或旧审核元数据，避免同 ID 原文更新后重新引入旧说法。差异说明同样保留关联引文的数量上下界；无法通过限定词校验时仅显示不含精确数量的覆盖差异。截断原文不补全未见内容，正文事实不得借注入指令添加行为者或因果。
