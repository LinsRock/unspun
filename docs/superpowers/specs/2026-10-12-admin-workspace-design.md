# M3 管理后台产品设计

日期：2026-10-12。状态：逐项产品方案已获用户确认；本文供整体复核，尚未开始代码实现或页面体验验收。

## 目标与边界

让唯一用户能够独立回答：系统现在是否正常、任意期间抓到了什么、费用花在哪里、哪些内容处理失败，以及如何有记录地干预。将当前滚动 24 小时运行报告扩展为历史可查询、明细可追踪的管理工作区。

后台排入 M3，按独立子项目交付：后台查询版 → 实时事件流排序与阅读体验 → 后台操作能力 → 兴趣与破圈。完整费用查询版包含固定费用的录入、周期规则及付款确认；这些账务操作不等待管线操作能力。各子项目分别设计实现与验收，不作为单个大 PR。正式 M3 任务板仍在 M2 收尾确认后建立，本次不宣告 M2 完成。

同日后续路线调整（D-016）：上述后台功能范围保持，后台操作之后先交付精选准入、事件进展和日报编排，再进入兴趣与破圈；完整顺序以 `docs/roadmaps.md` 的 M3-A–G 为准。任务基础在 M3-C 同时服务按源采集、内容处理和独立出版调度；精选状态、进展及选编理由随 M3-D–F 上线后补入后台，不作为查询版的前置条件。可选飞书内容推送在 M4 单独实施，不改变本设计不做外部续费通知的边界。

实时流默认最新事件与多排序按 D-014 和需求文档执行；本文只规定后台如何查询这些数据，不定义新的评分公式。周报/月报、外部账单自动同步、邮件或 IM 续费通知、多用户管理不在此次范围。

## 页面与交互

默认进入总览。桌面采用左侧导航与右侧工作区，沿用 `web/src/DESIGN.md` 的主题、字体、暗色与语义色；后台提高表格密度。手机支持总览、筛选、列表和详情，列表按重要字段折叠，不产生页面水平溢出。保留返回阅读页面入口。

原型反馈后的实现选型（2026-10-12）：后台用 React + TypeScript，基础日期、表格、搜索、表单校验、弹窗/抽屉及说明展开复用 Ant Design；图表复用 Recharts。业务代码负责查询口径与联动，不手写通用日历、分页、表单验证或图表坐标系统。`ConfigProvider` 映射现有主题，后台及图表路由按需加载。当前可体验原型在 `docs/design/m3a-admin-react/`，前两版静态原型仅留档；真实数据与页面验收仍按各阶段完成。

| 页面 | 主要内容 |
| --- | --- |
| 总览 | 当前状态、区间产出与费用、趋势、需要关注、最近运行 |
| 费用 | 全部运行成本、费用构成、调用明细、固定费用、付款与续费 |
| 信息源 | 配置清单、区间产出、健康状态、抓取记录、源详情 |
| 文章与事件 | 两个标签页，内容查询、处理状态、评分与来源详情 |
| 运行与任务 | 运行历史、待处理与失败、手动任务 |
| 配置与操作记录 | 信息源配置、管线与预算、变更与操作审计 |

列表支持搜索、筛选、分页、确定性排序，显示结果总数。筛选可通过 URL 恢复，列表进入详情后返回保留位置与筛选；排序偏好保存。总览数字、趋势图和汇总行下钻时传递时间与适用筛选，目标页显示筛选标签和清除入口。费用模型筛选只影响调用费用，不静默过滤固定费用；对应范围与小计明确标注。

## 时间与统计口径

默认时区 Asia/Shanghai。区间在 API 中使用明确起止时间，起点包含、终点不包含；今日/本周/本月/今年截至查询快照时刻，完整历史日期截至下一日零点。周一为一周起点。页面展示实际起止时间与数据更新时间。

快捷范围：今天、昨天、本周、上周、本月、上月、今年、自定义；另提供最近 24 小时、最近 7 天。自然日与滚动窗口分开。今日趋势默认按小时，跨日默认按天，年度默认按月，允许切换适用粒度。

| 指标 | 时间与范围 |
| --- | --- |
| 新入库文章 | `Article.fetched_at`，用户可切换按报道发布时间查询；缺失发布时间单独标注 |
| 新事件数量 | 系统首次创建事件时间，命名为“新建事件”；不冒充真实新发生事件 |
| 最新事件列表 | 所属文章最早有效报道时间，遵循 D-014；最新报道时间分别展示 |
| 抓取与运行 | 抓取/运行发生时间；跨区间运行的整轮详情保留其完整结果 |
| 调用费用 | 调用发生时间；所有有用量记录的重试和失败都计入 |
| 当前源数量与积压 | 当前状态，独立标注，不随历史区间伪装成历史状态 |

抓取成功率为区间内成功次数除以有结果的抓取次数，无记录时显示“暂无记录”，不显示 0% 或 100%。无新文章的成功抓取不是故障。明细与汇总使用相同区间与统计口径。部分数据缺失时标明缺失范围，不将未知值计为零。

## 总览

顶部为日期选择，默认今天。页面分四块：

1. 当前状态：worker 最近运行、可取得的当前阶段、待摘要/embedding/聚类/评分数量、当前异常源；不能将尚未采集的实时阶段或心跳推断为正常。
2. 区间结果：新入库文章、新建事件、抓取成功率、期间总成本与模型调用费用；每项可下钻。现有文档的“新事件”在总览使用明确的“新建事件”标签。
3. 趋势：按用途拆分的调用费用趋势，以及文章入库和处理趋势；固定费用纳入总成本构成，不能混入模型调用堆叠。
4. 需要关注与最近运行：持续失败的源、处理失败项、日报缺失/迟到、预算问题；展示具体原因、首次发现、最近结果和详情入口。正常时展示最近完成内容与剩余积压。

历史区间的费用和运行问题按所选范围展示；仍未解决的当前异常单独标为“当前”。预算提醒区分模型调用预算与系统总成本预算。

## 费用与固定账目

默认看期间成本，可切换实际支出。总览期间总成本包括模型调用、VPS、域名、存储、备份及其他手动维护项。

| 口径 | 规则 |
| --- | --- |
| 期间成本 | 调用按发生时间；固定/周期费用按覆盖期间分摊 |
| 实际支出 | 按确认付款日期统计；预付充值属于付款，不再次作为调用成本 |
| 待付与预测 | 周期规则产生待付款账目；尚未确认付款不计实际支出，预计成本与已确认成本分别标注 |

每项固定费用记录名称、类别、金额、币种、覆盖起止日期、周期、付款日期与状态、续费日期。支持一次性、月付、年付；站内续费提醒默认提前 7 天，可修改。规则生成账目以规则与覆盖周期唯一关联，重复执行不重复建账。停用规则不再创建未来周期；历史账目与金额版本保留。手动修正保留新旧值和原因。

固定费用按覆盖期间的自然日均摊，区间只计重叠日期；因此年付费用不会全部挤在付款月。未付款但已进入服务覆盖期的周期账目作为预计期间成本单列；付款确认后只转换状态，不叠加一笔重复成本。取消尚未发生的账目时不删除已确认历史支出。

自动记录模型调用费用；VPS、域名等首版由用户维护，后台不直接购买、续费或从外部支付账户扣款。预付模型账户充值只在实际支出账中记录；调用消耗仍按实际记录进入期间成本。充值余额不从不完整数据推算。

保留原币金额，用户选择汇总币种并维护兑换率与日期，首版不依赖实时汇率服务。账目/调用转换使用覆盖发生日期的汇率记录并保留依据；缺汇率时原币分别汇总，显示未换算部分，不给出貌似完整的总额。预算原币独立计算，不因页面展示币种改变限额。

费用页包含区间总费用、调用次数、输入/输出 token、平均每日成本、趋势、用途与模型汇总、调用明细及固定账目。平均值明确按区间已覆盖日数计算；金额保留足够精度，微小非零费用不能显示为零。调用明细支持 CSV 导出，并在可用时关联文章、事件、日报、运行或任务；批量 embedding 调用允许关联多篇文章，不能将一次调用全额重复分配到每篇文章。失败费用未知时显示未知，不冒充零成本。

本月模型调用预算始终独立展示，沿用现有 $50 月度预算口径；额外可配置系统总成本预算。历史筛选时明确预算组件仍对应本月。记录费用与供应商账单可有差异，保留来源，首版不做供应商账单自动同步。

## 信息源

默认异常优先，支持文章产出、失败率、最近成功时间、名称排序，记住上次选择。顶部区分当前配置总数/启用数与所选期间成功、有产出、失败的源数。

表格包含名称、语言、地区、类型、启停状态、健康状态、新入库文章数、成功/失败次数及成功率、最近成功、最近错误及其时间。最近错误必须取最近错误行，不以错误字符串大小冒充时间顺序。按名称、语言、地区、类型、启停与健康状态筛选。

详情包含地址/属性/权重/超时等配置、产出与健康趋势、逐轮抓取记录、文章列表。异常标识给出原因，连续失败、长期未成功、暂无运行记录和正常零更新分开。阈值作为可查看配置，与实际调度周期相容；实施前通过真实抓取记录确定阈值，不写死为任意健康结论。

已移除的源仍可从历史抓取/文章记录查询；没有历史配置版本时显示历史 ID 与现有可得信息，不将当前名称或属性冒充历史配置。后续配置变更开始保留版本。

## 文章与事件

文章页默认按入库时间倒序，支持切换报道时间、关键词、来源、语言、处理与内容质量状态；显示标题/原文链接、来源、两种时间、摘要/embedding/聚类结果和所属事件。支持分页和 CSV 导出。详情显示已提取正文、摘要、证据、错误、关联事件及可获得的调用费用，不自动为查看详情重抓原文或调用 LLM。

事件页支持关键词、来源、时间与处理状态筛选；排序与时间字段遵循 D-014，并明确区分文章数与独立来源数。详情展示摘要、分数组成/理由/评分时间、来源报道时间线、观点与证据、处理记录。实质进展时间线待进展识别能力交付后加入，不能用新增来源记录假扮。

查询版之后加入移动文章、合并事件、拆分事件：选择明确目标，预览文章归属及受影响派生内容，校验对象版本再提交。纠正不删除文章或原文；合并保留历史事件标识与操作记录，失效派生内容标记待更新。重新摘要、评分与观点生成通过有预算的任务执行。旧日报保留历史快照；这些纠正操作不回写旧日报。

## 运行与任务

运行历史展示开始/结束、运行中/成功/部分失败/失败、耗时、各阶段处理量和关联费用，支持日期、阶段、状态查询。详情列抓取、摘要、embedding、聚类、评分、观点、日报的结果与可用错误；单源失败不等同整轮失败，失败阶段也不能显示为成功。缺结束记录的历史运行显示“未记录”，不伪造耗时。

待处理与失败默认异常优先，列阶段、对象、错误、尝试次数/上限、最近尝试、自动重试状态和可用操作。只在实际记录支持时展示下次执行时间或消化时长。

手动任务首批包括单源立即抓取、失败文章重跑、指定文章重新摘要、指定事件重评分/观点生成，以及聚类纠正。任务队列展示排队、执行中、完成、部分失败、失败；记录提交者、参数、对象、预算授权、执行结果和费用。后台刷新或重复点击不会重复提交同一任务；定时和手动任务不能同时修改同一对象。过期对象、配置失效、重启中断与预算不足有明确结果，不能静默扩大范围重试。

默认遵守自动管线的预算限制，包括现有审核限额。提交前展示对象数与成本估计；无法精确估计时明确标注，仍须设置有限额度。超出常规预算时用户为该次任务明确额外费用上限、适用范围和原因，记录授权；不能改变后续自动任务预算。执行前预留额度，逐次核验，费用并发安全计入，不在多任务之间重复消费同一余额。额度不足停止后续调用并报告已完成部分；供应商费用尚未确认的调用保留待核对额度。费用上限是发起调用的控制，不承诺未知供应商计费绝对无误差。

## 配置与操作记录

长期修改走配置 PR：后台编辑草稿 → 展示新旧值与影响范围 → 校验 → 用户提交 PR → 待合并/待部署 → 已生效或部署失败。支持源清单/权重/抓取参数、调度/批次/模型/预算/评分参数；记录提交基准版本与部署版本，不将保存草稿或 PR 合并显示为线上生效。评分/提示词变更沿用标准事件集与 CI 要求，不绕过仓库评审。后台关联 GitHub 的凭证仅由部署环境配置，前端不持有。

临时覆盖仅用于紧急停源、暂停付费处理等已批准的操作，不任意覆盖长期权重或模型。填写原因，设置到期时间或明确手动解除；显示仓库值、生效值、覆盖来源、起止时间和解除状态。跨部署/worker 重启仍可追踪，失效后恢复当前仓库配置；解除与到期恢复也记日志。不得让固定费用账目或付款确认走配置 PR，它们是数据库业务数据。

审计包含操作者、时间、动作、对象、新旧值、原因、关联任务/PR/部署与结果；敏感字段脱敏。凭证仅显示配置状态，通过现有环境管理。后台不提供购买/支付、永久删文章/事件、删表或修改旧日报快照的操作。

## 架构与数据流

复用 React SPA、FastAPI、Postgres、worker 和 Cloudflare Access，不增加公开端口。后台作为独立路由工作区，旧 `/report` 提供通往总览的兼容入口；查询页按功能拆分组件与 API，不让现有 `ReportPanel` 成为全部后台的单体。

| 单元 | 职责与数据来源 |
| --- | --- |
| 查询与统计 | 从已有文章/事件/抓取/调用记录读取，统一区间解析和聚合口径，分页与索引支持历史查询 |
| 费用账目 | 独立周期规则、账目、付款、汇率与成本分摊；与调用记录组合汇总，不复制调用费用 |
| 运行与任务 | 扩展阶段记录、调用关联和可恢复任务状态；worker 消费任务，查询页读取进度 |
| 配置与覆盖 | PR 草稿/版本/部署状态，有限临时覆盖与生效配置读取 |
| 审计 | 记录账务、配置、聚类与任务操作；对外统一可追踪关联 |

新表/字段走 Alembic 增量迁移，保留现有历史记录。调用记录需要补充结果与关联对象，运行记录需要补充阶段起止及错误；旧缺失数据标明“未记录”，不伪造补齐。付费调用的用量日志不能随业务处理失败回滚丢失。计费明细与业务对象重生成分开持久化并保证幂等。

API 在服务端检查现有 Access 身份；任何写操作校验身份、输入、对象版本和请求来源，后台路径和 `/api` 都必须受保护。详情中外部内容按现有 http(s) 外链规则展示。导出仅包含请求筛选范围、正确引用字段并避免表格公式注入。后台不缓存敏感管理响应供离线重放；网络断开时禁止提交写操作并保留未提交草稿。

## 错误与验收

查询失败展示错误与重试入口，不能将失败当作空列表或零费用；保留筛选。无数据、历史缺字段、费用待核对、未配置兑换率分别说明。长任务提交成功与执行成功分别提示，操作失败不悄悄显示为已生效。

关键验证：北京时间日/周/月/年边界与滚动窗口；筛选下钻一致性；汇总与明细对账；多币种缺汇率；年付分摊、跨年续费、停用与金额版本；充值与调用不双计；未知失败费用；任务幂等/并发/重启/预算/部分失败；配置草稿/PR/部署/覆盖到期；聚类变更后的引用完整性与旧日报不变。

历史数据不足与新增记录能力必须在验收中明确。适用后端迁移/集成检查及前端 lint/typecheck/test/build 按各子项目执行。每次页面开发都启动本地预览，提供手机与桌面体验步骤，用户明确验收后才提页面 PR（D-012）。本文确认不替代页面体验验收。
