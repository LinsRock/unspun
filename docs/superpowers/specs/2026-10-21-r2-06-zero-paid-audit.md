# R2-06 零付费审计与协议修复

本批从最新 main `a27fb73` 建立独立 worktree `r2-zero-paid-audit`。生成、embedding、付费重试均为0；原付费停止文件、生产新链关闭、$0.30累计池、$1.50评测分配、原七笔预留和全部首次失败保持。R2-06仍为2/4，用户认可null。新盲准备、后台、生产启用、R2-07+、清理和R3均不实施。

## 执行与验收

1. 两份账本分别作只读截面，登记所有未决请求、原错误、提供方ID、凭证和完整预留。每个可定位ID仅一次免费GET，最多32次加一次key读数，单次超时15秒、无重试/持续轮询。404、429和余额差额均不是零费用凭证；没有逐笔凭证不结算。真正凭证仅可走既有 `DatabaseJournal.reconcile` 入口，结算不恢复任何付费。
2. 对32份v4真实请求/响应及已有严格审阅逐笔离线复盘。旧原件、标签、分母、门槛、冻结散列和首次失败不可改写。协议重放成绩仅证明机械关联，不证明语义修复。
3. 审核模型只返回目标ID、支持状态和问题。服务端从持久化实际请求/响应、调用上下文、原决定/材料/引用映射/packet及租约生成绑定，并在返回后和CAS前重新验证；不提供给任意JSON补当前指纹的路径。四项审核不增加轮数，错包、缓存错配、重放、过期/晚返回必须失败关闭。
4. 重审160字符等界限的依据，保留旧失败；禁止截断事实、猜补JSON或降低引用/语义门槛。分类身份/贡献解耦、证据选取代替自由复述形成下一次单独冻结的最小方案和旧指标映射，本批不执行真实调用。
5. 新建隔离库迁移、完整回归、旧排序/冻结与故障测试；审查差异/受影响调用方，经PR/CI合并后核验部署、关闭状态、阅读和R2-04保护。证据追加到 `docs/acceptance/r2-06-zero-paid/`。

## v5机械协议

`MemberAuditContent`是唯一模型输出schema：`checks[{target,status,issues}]`和`issues`。不要求模型复制kind或任何指纹；旧binding/kind/approved/revised_decision字段一律作为额外字段拒绝，不在运行时剥除。审核输入仍指定kind和完整target集合，query-only和anchor-only材料隔离不变。

内部`MemberAudit`保留服务端kind、五项ReviewBinding，增加物理request ID、request/response/lease指纹。创建内部记录之前必须验证：当前task与TaskAttempt仍持有同一租约；账本stage/phase/purpose/model、对象、任务、attempt一致；费用已知、HTTP成功、提供方ID与原响应相同且无跨物理调用重放；根据同一payload构造器得到的实际请求散列与缓存logical key完全一致；调用返回内容与该账本原响应相同。模型没有输出这些绑定字段的职责。

服务端在HTTP返回后重新检查材料、决定及租约，在CAS前再次读物理凭证并逐项比较完整内部记录，同时沿用四项审核完整覆盖、原决定不变、所有target supported且无issues、topic revision和当前来源/材料资格门禁。无法定位调用、错包、错误缓存、修改后的response、另一个attempt的缓存及晚返回均拒绝。只允许同一有效attempt内的精确缓存复用；跨租约的旧审核不自动重新签发，恢复需要另行审定，不能把旧输出盖上新租约指纹。

契约升级为`r2-member-v5`，旧注册/任务不转换、不重启。无数据库迁移，无新模型/提供方路由。共享`chat_request`仅抽取原请求构造器，R1请求语义保持，全部账务价格与66559输出窗预留算法保持。

## 资源限制复核

| 限制 | 当前依据与实际观察 | 本批边界 |
| --- | --- | --- |
| 每事实160字符、推断240字符 | 历史工程输出体积约束，不是事实支持或跨语言质量阈值；4/15已返回判断JSON超限，共24个事实和1个推断，最长事实612、推断434字符。31个可解析响应均`finish_reason=stop`，没有token截断证据 | v5保持原限值和拒绝结果；不截断文本、不补写输出、不将超限independent计成功。未来若调整须重新登记输出字节/token上限，不能按这些暴露样本最大值调参 |
| query/anchor各≤4事实、每事实≤2引文、≤2推断 | 最多8事实、16引文、2推断；每条都要审核，限制主张/审核规模，不保证4条足够完整 | 超出资源边界失败关闭，不能丢弃事实后批准原决定；最小方案改用证据选择，避免无必要复述 |
| quote 8..8000字符、每材料可见12000字符、原scope/voice | 引文必须是实际可见段落连续原文，长文只展示已登记前缀；前缀有truncated标识。不能据缺少后文推断否定事实 | 不扩大边界，也不把前缀当全文；缺决定性上下文应uncertain/拒绝。自由事实文本不得按长度截断 |
| 审核≤20检查、每级≤10issues | 当前complete-basis最多4+4+2+4=14 targets；20覆盖该结构，缺项/重复/额外项仍拒绝；issues非空即拒绝 | 四项审核不增加。issues达到上限不允许删问题来通过 |
| 判断/审核4096输出tokens，原JSON截断重试8192；chat输入262144字节 | 防止请求无限膨胀；原HTTP JSON-only并非提供方强制schema。字符≠token，不作确定性换算 | 本批0真实请求/重试。保留既有传输分支以兼容原账本，未来登记的首次评测必须物理请求上限约束且不得自动重试未知请求；含reasoning仍按66559预留，不能按4096缩预留 |
| embedding24000字节、batch32768字节、1024维；召回32→12、每话题≤2锚点、≤4候选 | 既有有界召回成本/资源规则，完整snapshot参与版本键 | 不改向量、模型、检索门槛、旧排序；缓存精确版本复用不代表冷向量实测 |

160/240的质量依据不足是保留缺口。维持付费关闭使其不会通过隐式调参影响真实成绩；下一次契约应先减少不必要生成，再从总体资源上限确定边界，而非截短事实或放宽引用检查。

## 最小调用方案与旧指标映射（提案，未付费实现）

单一classification混合了“是否同一个具体事件/持续议题”的身份轴和“查询自身是报道、背景、观点、解释或转载”的贡献轴。task138既讨论同一被查事件，又主要增加人物背景/分析，模型用身份吻合替代了冻结的opinion/background判断。该问题不能靠把旧same_event改成可接受标签解决。

成员判断不需要另写一遍新闻事实。提案输出`identity`、`contribution`、`certainty`，选择query/anchor原段落的引用ID及严格原文span，并为主体/行为/对象/地点/时间角色/出处指向这些证据；未知与冲突显式保留。服务端展开原文和归属，不让模型自由复述人名、年份或补全日期。最小解释只保留关系判断的结构化原因与对应target，若仍有推断文本必须逐条独立审核，不能利用“证据选择”省去语义支持检查。引用相等仍不等于语义正确。

在现有四项独立审核隔离要求下，成功关联候选的最小计划是**1次结构化判断+query-only、anchor-only、relation、complete-basis共4次审核=5次生成**；确定独立仅1次判断，结构失败/任一不支持立即停止。无额外“事实改写/修复”轮、无多数表决循环。每查询最多4候选，最多4判断+16审核；按已注册精确版本共享向量，暖缓存0次embedding，冷边界最多query+12×2=25个不同材料版本（不是已测成本）。减少到更少审核的质量等价性尚无证据，本批不将合并审核当作已授权降门槛。

| 新轴提案 | 保留旧classification/评分口径 |
| --- | --- |
| same_occurrence + report，事件话题，身份/时间均有据 | same_event |
| same_issue + report，持续议题话题，范围有据 | same_issue |
| 有明确相关关系 + background/opinion/explanation | 对应background/opinion/explanation；不得因提及事件改为same_event |

此表只能作为下一版预先冻结的确定性投影，不能回写旧标签或将旧失败改通过。旧召回分母保持预期query-topic对，旧关联精度按首次明确关联输出及上述单值投影计分；多贡献无法单值确定则uncertain，不取“任一标签匹配”获分。严格最终覆盖仍要求完整依据和实际CAS，阈值≥80%；召回≥90%、关联精度≥95%、不合法写入0及所有挑战门槛不变。身份/贡献各自准确率只可新增诊断列，不替代旧指标。

## 恢复付费的必要条件

1. 由认证提供方逐笔凭证对账本次新增未知；404、429、ConnectError或余额差额都不够，原七笔保留保护。结算使用既有审核入口，保留原响应与reconciliation；结算成功仍不删除paid-stop、不改阶段、不重新领取旧未知请求。
2. 另行明确授权恢复，审查并冻结纠正后的契约、长度策略、最小调用/阶段及物理请求上限；保留$0.30同池累计139次/$0.07734293和所有未决预留，原总$1.50及价格/66559算法不改。当前新hold计入池后占用$0.10708893，余$0.19291107不是授权；单笔审核整额预留仍可能使恢复在HTTP前停止。
3. 先修复并登记法国归因范围、分析/报道、日期精度/冲突、人名等语义缺口，明确第一次输出不通过就保留失败；在同一模型/路由用有限已暴露材料验证，先跑登记的挑战，再跑暴露集。全部原数值/严格依据门禁和真实CAS竞争通过之前，不准备新盲。
4. 对上游429采用另行审查的有界恢复方案：保留提供方Retry-After（若有），按明确窗口最多一次预先登记的探测，等待至少max(Retry-After,15分钟)；只针对新登记、无未决费用的请求，不重发原未知请求。任一429/未知立即恢复全局停止，无自动重试、无路由/模型切换；不把key/余额GET当作生成可用性证明。当前生产每5分钟空转没有有界结束，尚未实现提供方级冷却，本批只核查和提出方案。
5. 真实自然完整冷/暖链费用、未执行13/17查询、真实日期/双连接CAS、转载双端及旧背景等缺口仍需按新登记取得；无法在原池内完成则停并交接，不自动扩额。新盲准备和生产启用均是后续独立门禁，恢复评测不自动启用生产。
