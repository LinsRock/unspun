## 1. R2 目标与交付边界

让同一版面既能呈现值得独立阅读的文章、帖子和视频材料，也能围绕一件事或一个议题整理来源、背景与实质进展。供给增量按内容贡献选择，推荐分别表达重要性、公共关注、个人兴趣和当前价值。

R2 先建立供给与选材基线，处理扩大使用前的查询和采样边界，再交付话题及混合阅读。来源观察可以与不依赖它的后端工作同时推进，单个平台失败不阻塞其他路径；缺失用户评价不阻塞确定性的工程修复，但不能据此宣称主观质量通过。

本阶段复用 React、FastAPI、Postgres/pgvector、Access、现有任务及统一调用账务。内容继续复用 `articles`、材料与派生表及当前新版处理所有权，不另建一条平行采集链路。手动收集、预测、完整作者订阅、通用知识图谱、完整后台操作平台和全量历史重处理不在本次范围。

## 3. 供给、采样与详情

### 3.1 分离三种上限

分别记录一次列表扫描的元数据上限、排入材料任务的上限、进入付费整理的数量或费用上限。具体字段名与数值在实现前固定，现有 `max_items` 的 legacy 行为继续兼容；新版配置仍须有界，HTTP 大小、来源范围与退避约束保留。

先识别已知身份与重复观测，再在新候选中做低成本时效/材料能力判断和处理选择。已处理首条不能持续占满新增处理配额；已知内容按既定周期复查更新，不能因优先新内容而永久忽略原文变化。来源关闭、材料不足、明显过期、预算延期和技术失败分别记原因。

扩大扫描不自动扩大材料、付费或发布范围。实现须同时覆盖 RSS、编辑版和原站列表适配器；生产参数变更单列前后配置、真实流量和费用场景，先保持当前八路与原范围。

### 3.2 来源增量选择

| 缺口 | 首轮候选 | 选择与排除边界 |
| --- | --- | --- |
| 国内社会动态与公共议题 | `thepaper-sidebar`、`netease-home`、`tencent-headlines` | 优先复用已交付适配，比较新增可读材料与重复贡献；报道不冒充社区讨论 |
| AI 与科技进展 | `36kr-newsflashes`，按缺口再评估量子位等既有候选 | 快讯和完整文章分开验证，科技商业分析不直接等于技术一手发布 |
| 社区观点与个人经验 | 知乎回答、微博、雪球等既有待接路径 | 单独验证真实正文、署名、时间及会话维护成本；榜名、问题背景不能补成社区结论 |
| 视频实际内容、科学/健康/环境等覆盖 | 继续保留覆盖缺口 | 可补真实样本；完整媒体内容能力和全领域补齐不作为全部话题后端工作的前置条件 |

首轮建议选择贡献明确的 2–3 条路径；这是实施规模建议，不是新增启用名单或必须凑足的数量。新增路径沿用适用的 R1 逐路径观察标准；周期或材料类型不同则先登记窗口与关键错误门槛，再开始观察。新华社纯署名、NYT 图片说明及其他已知失败回归保留，修复与新窗口通过前仍关闭。

### 3.3 详情可读性

详情按规范 ID 解析当前材料及其卡片、准入和审核版本；保留别名解析与环路检查。仍校验来源发布开关、材料范围、指纹、中文和证据准入。退出推荐时效窗口的合格旧材料可以作为话题背景继续阅读，并明确原始日期；来源停用、结果失效或未通过审核仍不可借详情发布。

列表候选溢出不应使一个已知合格对象的详情整体不可用。导读请求继续显式提交、去重并遵守当前材料及预算限制；原文或身份变化时失效对应派生结果，不以“历史背景”为由恢复失效文本。

信息流候选范围按时间与各召回通道明确，最新仍按原始发布时间；不能以最早的数据库 ID 截断形成永久遮蔽。候选范围、来源/领域贡献与边界外遗漏在同批基线中比较，保护上限与稳定分页共同验证。

## 4. 话题、成员与实质进展

### 4.1 最小数据职责

| 对象（建议名称） | 最小职责 | 约束 |
| --- | --- | --- |
| `topics` | 标识事件或议题，保存名称、领域、状态及当前合格版本引用 | 企业、人物或领域不是自动归并依据；只为有持续整理价值的对象建话题 |
| `topic_items` | 关联话题与规范内容，保存关系类型、判断版本、材料引用及依据 | 多对多；区分报道、背景、观点、解释、重复转载；保留关系变更历史 |
| `topic_updates` | 记录实质变化、证据、时间含义/精度/依据及撤销或修订关系 | 进展可以未知时间；发生时间与报道时间分别表达，不能由抓取或处理时间补造 |
| 话题派生版本 | 保存中文概况/导读、成员材料集合指纹、模型/提示/审核版本 | 每项主张可追到具体材料与片段，成员或材料变化使受影响版本失效 |

表名、索引和 JSON 契约在对应迁移/接口批次固定。增量迁移保留旧表、日报和账务，旧 `Event` 只在单独核验成员语义后才可映射，不做默认全量转换。话题派生与 R1 card/guide 契约分开，避免为了增加话题标签强制重生成全部卡片。

### 4.2 处理链路

1. 从合格且确需归并的内容提取轻量主题/主体/时间信号；复用已取得的材料，按需生成向量。
2. 用领域、主体、时间与向量召回少量候选，再判定同一事件/议题、相关背景或独立内容。相似度本身不能确认成员关系，不确定时保留独立展示。
3. 在有版本的成员材料上识别背景、观点、转载与实质新增；生成结果与语义审核保存各自证据。议题中新出现且有材料支持的讨论焦点也可构成实质变化，保留发言者与观点归属，不以观点数量证明论断属实。
4. 只有通过中文、材料范围、归属与证据校验的话题版本才进入公开混合流。单条合格内容不因话题失败或延期而被撤下。

话题任务使用现有 Postgres 队列、短事务与领取版本；向量、成员判断、进展和导读分别可恢复。逻辑去重键覆盖对象、成员/材料集合、契约与模型版本；业务失败不能回滚已发生的物理费用，重复请求复用已完成结果。

后台只补必要的成员、关系依据、版本、失败和费用下钻，以及可审计的最小纠错能力。移除成员后重算受影响结果；停用来源后，旧话题缓存不能继续暴露仅由该关闭材料支持的主张。

## 5. 混合推荐、关注与时间

重要动态、个人兴趣内容及有真实公共关注信号的候选分别召回，再融合阅读价值、当前价值及多样性。公共关注暂缺时明确缺失；来源条数、转载数量和标题措辞不直接当热度或重要性。旧地区/语言折扣不自动复制到新版，变更须说明适用范围并通过固定评测。

同一版面优先避免重复概况，保留有独特解释、观点或体验的独立内容。候选选择、版面抑重和可读内容留存分别记录；不因话题卡出现而永久隐藏其所有成员，也不从点击、时长或滚动推断已读和兴趣。

接口继续复用 `/api/feed` 并增加明确的内容/话题类型标识；独立详情沿用 `/api/contents/{id}`，话题详情建议 `/api/topics/{id}`。反馈目标以类型加 ID 区分；原内容反馈与撤销继续兼容，主题词关注不自动变为话题订阅。话题反馈不自动扩散为对全部成员、作者或领域的态度。

“最新”中，内容按有依据的原始发布时间，话题按合格实质进展的明确时间口径排序；仅新增转载、导读、成员观测或没有实质变化的观点不会刷新进展。日期未知排后并标注。推荐、最新共用对象身份和详情，固定排序/候选版本、稳定分页与返回位置；偏好或材料修订继续有明确的游标冲突处理。

页面交付时将新版混合阅读设为主入口，原事件流与日报保留历史入口。当天精选版本、自动选编节奏和完整首页属于 R3，不能把旧固定日报改名记成新版精选。

## 6. 评测与不同分母

R2 首份基线先记录代码、配置、材料、版本、来源范围、观察时间和实际模型调用；旧 43 条候选及人工栏原样保留。建议另外采集 20–30 条近期真实候选，覆盖入选与排除、短讯与长文、部分材料、旧知识、转载与独立观点；用户遗漏参考建议约 5 条。数量是首轮建议，无法取得的材料和评价保持缺失。

算法或提示变更前，冻结真实输入及 AI 技术期望，保留未参与调试的留出材料。归并样本须包含同主体不同事件、跨源转载、真进展、不同观点、部分重叠、多话题、旧背景及未知时间；合成案例只验证工程边界，不能替代真实归并质量。

| 指标 | 分母及解释 |
| --- | --- |
| 列表发现漏斗 | 有界响应内可识别条目 → 留存的不同身份 → 可用材料 → 尝试整理 → 合格准入 → 当前公开 → 实际展示；重复观测不算新内容，各阶段注明时间与范围 |
| 来源覆盖 | 用户真实遗漏参考中，系统在约定窗口内发现的比例；没有参考集合时只报告覆盖缺口，不报告端到端召回率 |
| 已采集范围的筛选召回 | 已采集且有真实用户评价的值得看内容中被保留的比例；与来源覆盖分开 |
| 值得看比例 | 有用户评价的展示内容中值得看的比例；未评价不当否，也不进入已评价分母 |
| 版面重复与独立价值 | 同一快照中重复概况及被抑制的独特内容，结合关系标签检查误去重 |
| 归并与进展 | 固定真实材料上的误合并、漏归并、转载冒充进展及时间/归属/范围错误；技术审阅身份与用户意见分别标明 |
| 成本 | 每百条尝试候选、每条当前公开内容、每个话题版本/实质更新和每份新导读；失败、重试、未知预留另列 |

用户“感兴趣”反馈保持原语义，不直接转换成“值得看”或客观重要性标签。无用户评价时可完成工程契约与技术评测，主观效果继续留待实际反馈；来源字段或计数当前未采集的，也不从日志成功推算出完整发现量。

## 7. 预算、发布与回退

当前执行约束来自 D-027/D-028 与代码：项目 $15/月、生产 $13.50、原评测累计分配 $1.50，原模型及生产审核 $0.40/24h 保留；需求中的 $20–50 范围不等于本次可用额度。R2 不自动获得一份新的评测分配，原费用、差额 carry 和未知预留继续占用原账本。

新增 embedding、话题判断、进展、概况/导读及审核全部先过共享总额与各阶段预留。当前费用上下文没有话题阶段，须在调用前显式接线、登记阶段分配并使分配仍服从原生产总额；不能通过更换 stage 名获得额外空间。单位费用与真实流量未测时仅登记假设，生产扩量前刷新提供方与原账本只读读数，按剩余月份、失败/重试及导读场景投影。

每批按实际影响运行检查，数据库测试使用新建迁移隔离库；不向生产或保留评测库运行清理型测试。本机共享虚拟环境的 editable 安装曾指向旧 worktree，后续先核对实际导入路径，显式使用当前源码，避免测试另一份代码。

评分/提示/归并变更需通过冻结样本及必要旧回归。页面按 D-012 提供真实 API 本地预览，在用户实际体验通过后提 PR；R1 的 D-025 最终统一验收例外不自动延伸。纯后端与文档按现有审查、CI 和 PR 流程交付，不增加逐任务审批。

发布先只读或隔离验证，再有限配置启用；实际记录目标版本、来源/材料范围、新任务/结果、恢复与费用。回退关闭新增路径/话题发布并保留 R1 独立阅读、历史任务和账务；旧生产 worker 始终保持 0，不以回退恢复旧付费循环。

旧文档按当前规范、历史原件与无用副本处置，文档和开发残留可先独立交付。时效不再适合推荐的内容不直接等于无用数据，存储清理须检查历史阅读、身份/反馈、材料与话题、任务/配额、冻结评测及费用引用；大块无引用缓存和可重建临时数据在保留规则下回收。本轮只新增安排，不执行删除或更改既有功能状态。
