# R2-03 候选检索与合格详情分离

日期：2026-10-20；实施基线 `3a67836`。仅 R2-03 及 R2-02 自然轮次只读补证；CL-00/01 交统领 session 后续安排，R2-04+、清理和 R3 不执行。

## 详情与推荐的职责

按 ID 先解析规范身份，保留不存在/非 R1 的 404 与别名环路/超过 64 跳的 409。然后只查询该规范内容的当前材料及同指纹的 card/features/admission；三者均须 ready、当前卡片/审核契约、布尔 approved=true、材料及元数据指纹一致。来源所有权、发布开关与材料范围保持原规则；本机评测预览仍走原鉴权。最后重算现有处理指纹、解析卡片并验证中文、证据、include 与可用材料。没有 legacy 或旧派生回退。

详情不再调用推荐候选或排序，也不再用年龄撤销曾经合格的材料。过期新闻/短讯及超过 90 天的分析退出推荐后，合格当前版本仍可按原日期阅读；未经整理的旧材料、原本 rejected/invalidated 的结果不因此变合格。显式导读请求沿用原去重、取材、时效与预算限制，GET 不触发工作。

## 有界候选

SQL 先限定规范 R1 身份、当前材料、三类同版本合格派生和来源/范围，历史材料及旧派生不占候选槽。原时效谓词不变：短讯 48 小时，元数据新闻/旧报道 14 天，卡片分析/观点 90 天、问题 7 天、其他动态 14 天，知识/评论无统一年龄淘汰；缺有依据的原发时间保持未知。

在此范围内按来源及三类候选（有日期动态、有日期知识/评论、未知原发日期）分组，每组按真实原发时间降序、规范 ID 降序分配行号。按组内行号轮转，再以原发时间和 ID 确定同轮顺序，最多召回原 `max_candidates=1000`；名额不足时其他组自然补足。不按最早 ID 截断、不提高上限，不因历史总量或合格当前候选超过上限返回整体 503。范围外或名额外仍可按 ID 阅读；此上限是推荐召回范围，不声称全历史无遗漏。分组只决定召回，原权重、兴趣/反馈、软多样性和 latest 排序不变；新增话题/多通道推荐留给 R2-08。

数据库仅在有界 ID 选出后读取正文和卡片，批量读取渠道，避免逐内容 SQL。SQL 的原发时间提取与 `publication_at` 保持 original 优先、否则首个 editorial/question_created；日期用上海时区做内部比较，feed/modified/reprint 不冒充原发。无效日期安全归未知，再由原 Pydantic 契约拒绝；不在 SQL 中不受保护地 cast 外部日期。

## 游标、查询与验证

API 字段、游标格式、排序版本、15 分钟 TTL、400/409 语义保持。快照增加候选检索版本、当前材料/元数据及三类审核版本，来源发布范围也参与指纹。新候选晚于快照不会挤入旧页；被选版本失效/材料修订、来源范围或偏好改变时返回 409。各页使用相同 as_of 重建相同的有界候选并执行原全候选多样性排序。

使用新建迁移隔离库，所有生成/审核均 mock。验证 >1000 历史和 >1000 合格当前候选、来源/类别贡献、日期/未知边界、旧知识/背景、过期新闻、各派生失效/审核版本、材料修订、别名/环路、来源范围、稳定翻页/冲突及 GET 无任务。记录查询条数、载入量、EXPLAIN ANALYZE/BUFFERS 与耗时；必要索引增量迁移。冻结 v1、scan v2 和空用户评分不改，新对照登记 v3。

R2-02 补证只读 REPEATABLE READ 事务、免费 GET /key；保存带时间收据、任务/材料及费用，检查逻辑槽、复用和未完成链路。不能为取得重启/重放/错误场景而手动生产触发。费用沿用原账本、模型和分配，新增付费评测 0。
