# M3-B 排序与阅读样本准备

2026-10-14 只读收集。当前不是完成的标准事件集。

- `m3b-evidence.json`：现有开发数据集中 12 篇晚抓文章元数据，以及既有内容质量回归里的 5 个生产审计短摘录。保留原始文章 ID、URL、报道与入库时间，不写业务数据。
- 开发库当前 0 个事件，不能导出真实事件排名或现有分数。文章样本没有擅自归为同一事件。
- 历史审计摘录中发布时间未经排序用途核实；其旧内容质量期望也不是重要性标注。不可直接放入排序基线。
- [实施设计](../superpowers/specs/2026-10-14-m3b-feed-reading-design.md) 记录推荐规则、候选公式及验收边界。

需要的人工标准集包含 30–50 个真实事件，人工确认成员文章、有效时间、媒体分组、明确转载关系、重要性档位及“值得读”的判断。排名优先关系分别按最新事件、来源活动和重要优先标注，允许无明确偏好。不得用 AI 自动补满人工评分。

必须覆盖：晚抓旧闻、旧事件新增转载、同媒体多栏目、同媒体重复、跨媒体已知转载、少报道但重要、未知时间、明显未来日期、可信旧日期、北京时间今天与滚动 24h 边界。样本冻结后固定输入和哈希，不用临近验收改阈值来解释通过。

建议单事件标注结构（仅结构示例，不是真实标注）：

```json
{
  "event_id": 123,
  "article_ids": [456, 457],
  "timestamp_review": "pending",
  "publisher_groups": {},
  "known_reprints": [],
  "importance_band": null,
  "worth_reading": null,
  "reviewed_by": null,
  "reviewed_at": null
}
```

`pending` / `null` 必须被评测就绪检查拒绝，不能默认为通过。代码回归的合成边界输入与人工真实事件集分开保存。
